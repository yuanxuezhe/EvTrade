## git 仓库损坏与恢复（下午）

验证冒烟测试时误用 `git stash`，pop 失败导致 .git 对象库大面积损坏：refs 目录消失、loose objects 全空（含两个未推送提交 ead8594/f26754b）、commit-graph 引用丢失对象。

### 恢复过程
1. 从 pack 找到最新可用提交 1c07d45d，重写 master 引用
2. 工作区文件未受影响（stash 只动 git 对象库）——脚本功能 + KB 审计改动完好
3. 清理损坏的 reflog/commit-graph 后 `git gc` 误删全部 commit 对象（教训：gc 前必须先确认 refs 存在）
4. 从工作区重建快照提交 → 远程 fetch 恢复完整 1025 提交历史（fetch 网络需重试）
5. `git reset --soft origin/master` 把工作区嫁接回旧历史，合并为一个提交 e30534f
6. push 成功，工作已备份远程

### 重新执行历史版本标注清理

### 教训
- **禁止在对象库可疑时执行 `git gc`**——gc 会按可达性清理，refs 一旦丢失会连带删除全部历史
- 恢复顺序：先救 refs → 再 fetch 远程 → 最后才考虑 gc
- git stash 在 Windows + 中文路径项目上有损坏风险，改用分支暂存
