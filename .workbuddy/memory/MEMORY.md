# 项目记忆 — 长期约定

## 最高工作准则（2026-08-16 立，用户拍板）

1. **知识库驱动开发**：`E:\EvTrade\知识库\` 是唯一事实来源。任何修改必须**先改知识库、再改代码**，顺序不可颠倒。详见 `知识库/全局规范.md`。
2. **同步修改**：改代码必须同步更新对应知识库文档；知识库文档中的「对应代码路径」锚定了可修改的文件范围。
3. **改动范围最小化**：只改知识库中描述到的模块对应的代码，禁止大面积无关重构、禁止顺手优化无关模块。
4. **测试范围控制**：只写/只跑涉及改动模块的测试，禁止全量跑测试浪费时间。改动范围判定方法见 `知识库/全局规范.md` §3.2。
5. **知识库规范**：目录与文件名用中文；单文件 ≤300 行，超了拆分；每个文档含固定章节（对应代码路径/功能概述/文件清单/核心实现/依赖关系/修改指南）。
6. **禁止历史版本标注**（2026-08-22 立）：代码注释和知识库只写现状，禁止 "vNN"、"YYYY-MM-DD 改动" 这类历史叙事；历史变化用中文 git 提交说明承载（git log/blame 可追溯）。例外：REQ-xxx 编号、openspec change 目录名路径引用、库名/协议版本。
7. **与 openspec 关系**：openspec/specs = 能力级需求（WHAT）；知识库 = 实现级事实（HOW）；docs/ = 历史归档不更新。
