# REQ-FE-553: 业务文件必须用 element-plus 子路径 (2026-09-23 bundle-shrink-round-3)

## 背景

`REQ-FE-551` + `REQ-FE-552` 仅消除 main.js + layout 4 组件 (Sidebar/AppHeader/OperationLog/BottomNav) + Login 三个文件的
`from 'element-plus'` 整包路径. 项目里**还有 27 个 view/composable/store 文件**仍写整包 — vite dev 首次访问
任一文件都会触发 deps prebundle 生成 `element-plus.js` 88KB bundle. 这虽然不污染主图 (因为路由 lazy),
但每次打开一个未访问过的 view 都会有一次额外的 prebundle + reload, 慢且不可预期.

## 新增规范

### REQ-FE-553.1: 业务文件 100% 走 `'element-plus/es'` 子路径

禁止:
```js
import { ElMessage } from 'element-plus'                       // ❌
import { ElMessage, ElMessageBox } from 'element-plus'         // ❌
import { ElNotification } from 'element-plus'                  // ❌
import { ElLoading } from 'element-plus'                       // ❌
```

正确:
```js
import { ElMessage } from 'element-plus/es'                    // ✅
import { ElMessage, ElMessageBox } from 'element-plus/es'      // ✅
import { ElNotification } from 'element-plus/es'               // ✅
import { ElLoading } from 'element-plus/es'                    // ✅
```

### REQ-FE-553.2: API 范围 (FE-553 拍板)

本项目用到 element-plus API 仅 3 个:
- `ElMessage` (22 文件)
- `ElMessageBox` (8 文件)
- `ElNotification` (1 文件, `stores/ws_dispatch.js`)

3 个 API 都在 `element-plus/es` 命名导出里 (确认 v2.5+ ESM tree-shake). 无 ElLoading/ElImage 等稀有需求.

### REQ-FE-553.3: 派生的 unplugin 行为

改完子路径后, 原本 unplugin 在该文件头插的 `/* unplugin-vue-components disabled */` marker 消失,
模板里 `<el-button>` / `<el-icon><Edit /></el-icon>` 重新被 resolver 自动按需注入 import + register.
