# REQ-FE-554: view 私有子组件必须 defineAsyncComponent (2026-09-23 view-lazy-stage-a)

## 背景

REQ-FE-551/552/553 已把 main + layout + 业务 file 的 element-plus 整包清, 但路由 lazy 到 view 后,
**view 内部仍 eager import 大子组件**, 单次 mount 一次性拉全部:

- Trade.vue (16 KB chunk) → 4 子组件 (OrderForm / QuotePanel / TodayOrdersPanel / HoldingsPanel)
- T0Trade.vue (34 KB chunk) → 7 子组件 + 4 store
- Dashboard.vue (7 KB chunk) → EChart 含 echarts
- Asset.vue → EChart 含 echarts

这些组件 mount 后才需要, 不应在路由 setup 阶段就 eager.

## 新增规范

### REQ-FE-554.1: view 私有子组件 import 必须 defineAsyncComponent

业务 view (Trade / T0Trade / Dashboard / Asset / 等) 引本地 .vue 子组件时, **禁止**静态:
```js
import OrderForm from '../components/OrderForm.vue'                    // ❌
```

必须 defineAsyncComponent:
```js
import { defineAsyncComponent } from 'vue'
const OrderForm = defineAsyncComponent(() => import('../components/OrderForm.vue'))   // ✅
```

### REQ-FE-554.2: 子组件 chunk 由 vue-router / vite 自动分裂

- 每个被 defineAsyncComponent 包装的组件路由到 view 后, vite dev 按需 fetch 单独 chunk
- build 阶段 rollup 自动给每个组件一个独立 .js chunk
- 浏览器第一次 mount view 时拉该 chunk, mount 完成后即可用

### REQ-FE-554.3: view template 用法不变

`<template>` 里的 `<OrderForm ref="orderFormRef" ... />` 写法与静态完全一样, defineAsyncComponent
不影响 Vue 编译器, 不会改动 render 函数.

### REQ-FE-554.4: 排除 — view 私有 store 仍 eager

view 私有 store (useXxxStore()) 不进 defineAsyncComponent, 仍 eager import:
- 复杂 (Pinia 动态注册)
- lazy 引入 store 会导致 setup 阶段 state 顺序问题
- Stage A 范围只动 component, 不动 store
