# 其他状态

## 对应代码路径

- `client/src/stores/t0_tasks.js`（155 行，T0 任务缓存）
- `client/src/stores/stocks.js`（445 行，证券基础信息）

## 功能概述

这组 store 覆盖交易主链路之外的状态：T0 任务管理（REST CRUD + 乐观更新）、证券基础信息（IDB 秒开 + 全量缓存 + 分页表格）、股票信息爬取同步（REST 兜底 + WS 增量进度）、全局 UI 偏好（主题/侧栏/快捷键/断点）、以及 strategy store 的纯函数 helpers。共同特点：与 holdings 单源体系解耦，各自独立 RPC/IDB 数据源。

## 核心实现

### t0_tasks.js（v18 t0-task-management）

- state：`tasks`（整体覆盖式刷新）、`tasksById` 索引、`overviewData`（后端扁平统计：total_realized_pnl/active_task_count/avg_win_rate 等）、loading/error/lastUpdated。
- getters：`activeTasks`（status==='active'，T0Trade 下拉源）、`tasksByStockCode`（同券多 task 分组）。
- `loadTasks(opts)`：`Promise.all([t0TasksApi.list, t0TasksApi.overview])` 一次拉全（百个规模内不增量）。
- CRUD 均乐观同步本地：`createTask` push + 建索引；`updateTask` in-place 替换；`archiveTask` 调 remove 接口后把本地 status 改 'archived'；`closeTask` 直接透传（实际下单）。不持有派生 summary，避免双源漂移。

### stocks.js（v90/v97 缓存体系）

- 内存：`cacheMap = reactive(new Map())`（code → stock，O(1) 查）；兼容层 `cache = computed(() => Array.from(cacheMap.values()))`。
- IDB：DB `EvTrade-stocks` v2，store `stocks`，key = stock_code（v97 从单 key 'all' 重构为逐条 key，单条 put 不需全量覆盖；onUpgrade 删旧 v1 kv store）。
- 启动：`initCache()`（单飞 `_initPromise`）→ `loadFromIDB()` 秒载 Map；IDB 空才阻塞 `refreshCache()`（GET /api/stocks/all 全量 + `_persistIDB` clear+逐条写）；**有数据则不后台刷新**，手动同步走证券信息页按钮。
- `searchCache(query, limit)`：三列 substring 打分（代码前缀 3 分 > 代码包含/简称前缀 2 > 简称/名称包含 1）；v113 空 query 也返回前 limit 条。
- 分页：`fetchPage/setPage/setPageSize`（后端真分页 page/page_size + total）。
- 编辑/添加：`openEdit/closeEdit/saveEdit/createStock`，成功后 `upsertLocal`（Map + `_persistSingleStock` 单条 IDB put）+ pageRows/total 同步。
- 查询 helper：`stockName(code)`（null 表示未命中）、`stockScale(code)`（价格小数位，兜底 2）、`stockStktype(code)`（0 股票 / 1 ETF）。

### sync.js（v21 stock-info-crawler）

- state：`task`（REST 返回 shape）、`liveProgress`（WS 增量覆盖 current_code/eta_sec/processed）、`errors`（最近 100 条）、`wsConnected`。
- REST：`start/stop/refreshStatus`（POST/DELETE /api/sync/stocks + GET status）。
- WS 事件处理（ws_dispatch 调入）：`onSyncStarted`（初始化 task 骨架）、`onSyncProgress`（job_id 守门，只覆盖进度字段）、`onSyncCompleted/onSyncFailed/onSyncStopped`（改 state 终态 + finished_at）、`onStockSynced`（单只 inserted/updated/skipped/failed 实时计数）。
- computed：`isRunning/isFinished/percent/currentCode/etaSec`（liveProgress 优先、task 兜底）。

### ui.js

- 主题：`theme`（localStorage 'evtrade-theme'），`toggleTheme` 同步 dark class；store 初始化时即应用。
- 侧栏：`sidebarCollapsed`（localStorage 'evtrade-sidebar'）；移动端是 `mobileSidebarOpen` 抽屉；`toggleSidebar` 按断点分流；切回桌面自动关抽屉。
- 断点：`MOBILE_BP = 900`，resize 监听；URL `?mobile=1` 强制移动端（调试）。
- `oplogExpanded`：操作记录栏折叠态（OperationLog v-model:expanded 共享，Trade.vue 视口计算要读）。
- `t0Keybindings`：T0 快捷键开关（localStorage 'evtrade-t0-keys'，默认开）。
- `onRouteChange`：路由切换关移动端抽屉（App.vue 调）。

### strategy_helpers.js（strategy store 拆分件）

- `createPendingTracker()`：pending Set + isPending/setPending（每次 `new Set(...)` 换引用触发响应式）。
- `upsertStrategy(list, strategy)` / `removeStrategy(list, id)`：按 id in-place 维护。
- `setAuditCache/appendAuditCache/clearAuditCache`：按 (id, trdDate) 嵌套的 audit 缓存维护。
- 全部纯函数、无 store 依赖、可单测（strategy store 本体在 views 侧使用，store 目录仅此 helpers）。

## 依赖关系

- t0_tasks → api/t0_tasks；T0Trade.vue / T0TaskList.vue / T0TaskDetail.vue 消费。
- stocks → api/stocks + utils/idb.js；StockCodePicker / AdminStockConfig / usePricePrecision / utils/stockNames 消费；App.vue 启动调 initCache。
- sync → api/sync；ws_dispatch 的 sync_* 帧调入 onXxx；证券信息同步页消费。
- ui → 仅 Vue + localStorage；App.vue / Sidebar / AppHeader / T0Trade / OperationLog 消费。
- strategy_helpers → 无依赖（被 strategy 相关视图层 store 逻辑使用）。

## 修改指南

- **t0_tasks 加字段/筛选**：loadTasks 整体覆盖模式下直接扩展；新增 getter 从 tasks 派生，不要另存副本。
- **stocks 缓存策略**：改 IDB 结构需 bump version 并保留 onUpgrade 的旧 store 清理；新增查询 helper 沿用「cache miss 返回兜底值（null/2/0）」约定，让调用方决定占位。
- **sync 新增推送事件**：ws_dispatch 加 type 分支调新 onXxx，注意 job_id 守门防串任务。
- **ui 新增持久化偏好**：一律 localStorage + 初始化时读取应用，key 用 `evtrade-` 前缀。
- **strategy_helpers**：保持纯函数约束（无 import store），策略逻辑变更时同步补单测。
