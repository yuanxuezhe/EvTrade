## 功能概述

holdings 是全站**单一权威缓存**（v8）：orders / trades / positions / cachedAsset 四类核心交易数据只在这里。order/position/asset 三个 store 均为它的 facade（见 交易与资产状态.md）。为避免单文件膨胀，采用「工厂注入 refs」拆分：holdings.js 持有全部 state，把 refs 注入各 helper 模块的 createXxx 工厂，返回的方法 spread 回 store 返回值。

数据流：

```
bootstrap ─┬─ IDB 优先（命中跳过 RPC orders/trades）
           └─ 4 路 RPC (Promise.allSettled) → applyXxxResult（写 IDB → 写 ref）
WS 推送 ──→ applyOrderPush / applyTradePush / applyPositionUpdate（守门 + 增量 upsert）
quote.tick → liveMarketValue computed → 写回 cachedAsset（watcher）
```

## 核心实现

### holdings.js — state 与装配

```js
// 核心数据
positions / orders / trades        // 当日三表
cachedAsset                        // 资产快照（v99 起 ws asset_update 也覆盖）
activeTrdDate / activeDayStatus    // 激活交易日及其状态
// 运行时
loading / bootstrapped / lastUpdated / refCounts / idbSyncStatus
initializing                       // 系统初始化 gate（ws_dispatch 丢帧判定用）
loadHistory                        // 操作日志（createLogger 的 ref）
```

装配顺序：createLogger → createMarketComputeds → createPushHandlers → createDayPnlRecompute → createBootstrap（注入 `_startWs` 回调，避免循环依赖）。`_startWatchers/_stopWatchers` 管 daypnl 四个 watcher 与 `watch(liveMarketValue, …)` 写回 `cachedAsset.market_value/total_asset`。bootstrap/resetForNewDay 为包装版本（自动启停 watchers）。

### bootstrap（holdings_bootstrap.js）

```
_resolveActiveDay()                     // /asset/active-day → activeTrdDate
_tryIDBFirst()                          // loadAllOrders/Trades/Positions 全命中则跳过 RPC
Promise.allSettled([orders, trades, positions, asset])
→ applyXxxResult(...)                   // 写 IDB → yield → 写 ref → 翻 refCounts/idbSyncStatus
→ 启动 ws + _startQuoteAutoSub          // 订阅持仓证券行情
```

- `_startQuoteAutoSub`：持仓数 > FULL_MARKET_THRESHOLD(100) 时切全市场订阅 `['']`。
- `refreshAll`：clearAll → 4 路 RPC → applyXxxRefresh（merge 而非覆盖，返回 summary 字符串供 UI 展示）。
- `resetForNewDay(prevDay)`：clearDate(prevDay) 前缀清理 → 重置 state → 重新 bootstrap（由 day-init 推送触发）。

### apply 系列（holdings_apply_results.js）

- `_mergeOrders` 以 `trd_date + order_no` 为主键、`_mergeTrades` 以 `trd_date + order_no + trade_id` 为主键做 upsert。
- 统一节奏：**bulkSave IDB → await yield → 写 Pinia ref → 更新 refCounts/idbSyncStatus**，保证 UI 一次性渲染。
- `fillTradesDirection`：用 orders 的 order_no 反查填充 trade 空 order_type（broker trd_cfm 漏推方向的兜底）。

### 推送守门（holdings_push.js）

- `applyOrderPush(row, action)`：activeTrdDate 守门 → cancel-row（order_flag=1，user_def='CANCEL:xxx'）短路走 flattenCancelledByRow → metaMerge 保留 ref 累计字段（traded_volume 等不被 row 覆盖）→ statusRank 守门（rank 倒退丢弃，防乱序）→ _persistOrder + _invalidateT0Stats → 返回 finalStatus。
- `applyTradePush(row)`：activeTrdDate 守门 → trade_id 去重 → normalizeTrade（amount 本地算）→ _persistTrade → 用 order.order_type 填充方向 → _invalidateT0Stats。
- `applyPositionUpdate(row)`：按 stock_code find → 整条 ref 替换（v95）；找不到 → `_queueNewPosition` 100ms trailing debounce 批量 unshift。
- `applyQuote(row)`：positionCodes 白名单过滤 → quoteStore.update。

### IDB schema（holdings_idb.js）

```
DB: EvTrade-holdings-cache  VERSION 5
store orders    key = `${trd_date}:${order_no}`
store trades    key = `${trd_date}:${order_no}:${trade_id}`
store positions keyPath = 'stock_code'（inline key）
```

onUpgrade 链 v12→v13→v14→v5（v5 重建 positions store）。复合 key 无索引，按日清理用 `idbGetAllKeys` 前缀扫描（`clearDate(trdDate)`）。单行写为 fire-and-forget，批量走 `bulkSave(store, items, keyOf)`。`_resetForTests` 供测试 teardown。

### 当日盈亏（holdings_daypnl.js）

触发矩阵（全部 watch，无轮询）：

| 触发 | 动作 |
|---|---|
| quote.tick 自增 | recomputeAll() 写 `p.day_pnl / p.day_fee` |
| positions 引用变化 | recomputeAll()（bootstrap/换日立即算一版） |
| activeTrdDate 变化 | refreshDayPnl()（跨日清旧成交 map） |
| trades.length 变化 | 3s 防抖 refreshDayPnl(true) 强制重拉 |

计算委托 composables/useT0DayPnl（getDayPnl/getDayFee），不直接 import holdings（防环）。

## 依赖关系

- holdings.js → 5 个 helper 模块（工厂注入）；helper 之间不互相 import。
- holdings_push → quote store（applyQuote）、t0Stats invalidate（动态）。
- holdings_daypnl → composables/useT0DayPnl + quote store（tick）。
- holdings_idb → utils/idb.js；helpers → utils/orderCalc.js + utils/format.js。
- 上游消费者：order/position/asset store（facade）、ws_dispatch（推送入口）、App.vue（bootstrap）。

## 修改指南

- **新增 state 字段**：只在 holdings.js 声明；需要 helper 读写就通过工厂参数注入，不要在 helper 里 useHoldingsStore()（会循环依赖）。
- **新增 RPC 数据源**：bootstrap 的 allSettled 加一路 + apply_results 加对应 apply 函数（保持「IDB → yield → ref」节奏）。
- **改推送合并规则**：入口在 holdings_push.js，注意保持 activeTrdDate 守门与 statusRank 防倒退；累计字段语义改动需同步 utils/orderCalc.js。
- **IDB 改 key/store**：DB_VERSION +1 并写 onUpgrade 迁移；旧数据清理逻辑（clearDate 前缀）依赖 key 格式，二者一起改。
- **加新的 watcher**：挂到 _startWatchers/_stopWatchers，确保 bootstrap 失败或登出时能 stop。
