# 认证状态

## 对应代码路径

- `client/src/stores/auth.js`（142 行，Pinia store）
- `client/src/stores/auth_idb.js`（86 行，session 的 IndexedDB 持久化）

## 功能概述

认证采用 JWT Bearer 模式：token 存 localStorage（key `evtrade-token`，供 axios 拦截器同步读取）+ IndexedDB（跨会话恢复完整 session）。核心设计：

1. **hydrate 启动屏障**：main.js 顶层 `await auth.hydrate()`，从 IDB 恢复 session 到内存与 localStorage 后才挂载 router，保证路由守卫首次判定正确。
2. **hydratePromise 单飞**：并发调用 hydrate 只发起一次恢复。
3. **IDB 写失败不阻塞**：login 成功即返回，saveSession fire-and-forget；隐身模式等异常静默返回 null 走 /login。
4. **角色体系**：admin（管理员）/ trader（交易员）/ viewer（只读），computed 暴露 isAdmin / isTrader / isViewer。

## 文件清单

| 文件 | 职责 |
|---|---|
| stores/auth.js | token/user/loading/ready 状态 + hydrate/login/fetchMe/logout/updateProfile/changePassword/clear |
| stores/auth_idb.js | DB `EvTrade-auth` / store `kv` / key `session` 的 loadSession/saveSession/clearSession |

## 核心实现

### state（auth.js）

```js
const token = ref('')            // 内存 token
const user = ref(null)           // { username, role, ... }
const loading = ref(false)       // login 请求中
const ready = ref(false)         // hydrate 是否完成（启动屏障信号）
let hydratePromise = null        // 单飞 promise
```

### hydrate() — 启动恢复

```
ready=false → loadSession()（IDB）
  ├─ 命中: token/user 写内存 + localStorage('evtrade-token')
  │        可选异步 fetchMe() 校准 user（token 失效也不抛）
  └─ 未命中(隐身/首访): 什么都不做, 留给路由守卫跳 /login
→ ready=true, 返回 hydratePromise（并发复用）
```

### login() — 登录

```
authApi.login(x-www-form-urlencoded)
→ 拿 { access_token, user }
→ 内存 + localStorage 写 token
→ fire-and-forget saveSession({token, user}) 落 IDB
```

登出 `logout()`：调后端 logout（尽力）→ `clear()`（清内存 + localStorage + IDB clearSession）。路由守卫随后将其送回 /login。

### auth_idb.js — IDB 持久化

```js
const DB_NAME = 'auth', DB_VERSION = 1, STORE = 'kv', KEY = 'session'
// value 结构: { token, user, savedAt: Date.now() }
let _db = null, _initPromise = null   // 单例连接 + 单飞初始化
```

- `loadSession()`：读 key `session`，任何异常（IDB 被禁/隐私模式）返回 null 不抛。
- `saveSession({token, user})`：put 覆盖写。
- `clearSession()`：delete key。

### computed 角色判定

| computed | 条件 | 用途 |
|---|---|---|
| isAuthenticated | token 非空 | 路由守卫 / App.vue 切换 WS 连接 |
| isAdmin | user.role === 'admin' | requiresAdmin 路由 |
| isTrader | admin 或 trader | requiresTrader 路由 |
| isViewer | viewer | 只读 UI 降级 |

## 依赖关系

- auth.js → auth_idb.js（loadSession/saveSession/clearSession）。
- auth.js → api/index.js 的 authApi（login/me/updateProfile/changePassword/logout）。
- main.js 顶层 await hydrate()（启动屏障）。
- router/index.js 守卫读 isAuthenticated/isAdmin/isTrader。
- App.vue watch isAuthenticated 控制 WS connect/disconnect。
- api 拦截器读 localStorage('evtrade-token') 加 Bearer——因此 auth 写 token 时必须同步写 localStorage。
- ws_heartbeat 动态 import auth（token 过期时 clear + 跳登录），避免模块级循环依赖。

## 修改指南

- **改 token 存储位置**：auth.js 中 localStorage 写点（hydrate/login/clear）与 TOKEN_KEY 常量（api/index.js）必须同步改；axios 拦截器只认 localStorage。
- **新增用户字段**：后端 /me 返回结构变化时，hydrate 的 fetchMe 校准与 Profile.vue 展示同步调整；IDB 里旧 session 的 user 是快照，以 fetchMe 为准。
- **改角色模型**：computed 三连（isAdmin/isTrader/isViewer）与路由守卫 meta 分支同步修改。
- **改 hydrate 行为**：注意 main.js 顶层 await 是硬依赖，hydrate 必须始终 resolve（内部 catch 全部异常），否则应用白屏。
- **IDB schema 升级**：只动 auth_idb.js 的常量并加 onUpgrade；不要在 auth.js 直接操作 IDB。
