# 部署与反向代理 — nginx-proxy-manager cache 坑

## 网络拓扑 (EvTrade 2026-09-23)

```
外网客户端
  ↓
路由器 (公网 IP + 端口 NAT)
  ├─ :50443 → 192.168.10.2:50443 (路由器自身 openresty 另一侧)
  └─ :443   → 192.168.10.2:443   (docker nginx-proxy-manager)
              ↓
              docker proxy_pass http://192.168.1.2:50998 (本机 vite dev)
              ↑ 192.168.1.2 = 本机 IP (实测 192.168.10.2 同一台)
```

注意:
- **内网直连**: `http://192.168.10.2:50998/` (绕过 docker nginx) → ✅ 工作
- **HTTPS 域名**: `https://evtrade.ngx.evdata.top:50443/` → ❌ **not docker 范围** (路由器自身 openresty)
- **HTTPS 域名**: `https://evtrade.ngx.evdata.top:443/` → ❌ **docker nginx-proxy-manager 缓存整个 HTML/JS 30 分钟**

## 根因 (2026-09-23 故障)

`evtrade.ngx.evdata.top` 走 docker **nginx-proxy-manager**, 其 1.conf 包含 `assets.conf`:

```nginx
# /data/nginx/proxy_host/1.conf (evtrade.ngx.evdata.top)
include conf.d/include/assets.conf;   # ← 罪魁!

# /etc/nginx/conf.d/include/assets.conf
location ~* ^.*\.(css|js|jpe?g|gif|...)$ {
    proxy_cache public-cache;          # 30 分钟
    proxy_ignore_headers Set-Cookie Cache-Control Expires;
    proxy_hide_header Cache-Control;   # ← 吞掉后端 Cache-Control
    expires @30m;
}
```

**后果**:
- vite dev 返 `Cache-Control: no-store` —— 但被 `proxy_hide_header` 吞掉
- nginx-proxy-manager 强制 `expires @30m` (30 分钟)
- vite build 产物的 `chunk-CN2NG2UE.js` 被缓存 30 分钟
- 用户浏览器 SW `Cache-Control` cache 后 1 周 + heuristic cache
- 旧 chunk 名引用 → SyntaxError → "no active Pinia" → "Symbol(route location) not found"

## 修复 (手动, 容器外部配置)

### Step 1: SSH 进 nginx-proxy-manager 容器

```bash
docker exec -it nginx-proxy-manager sh
```

### Step 2: 编辑 /data/nginx/proxy_host/1.conf

删除这一行:
```nginx
include conf.d/include/assets.conf;
```

位置: `server { ... listen 443 ssl; ... }` 块内 `ssl_certificate` 之后, `location / {` 之前.

完整 1.conf 已修后片段参考:

```nginx
server {
  listen 443 ssl;
  server_name evtrade.ngx.evdata.top;

  ssl_certificate /etc/letsencrypt/live/npm-6/fullchain.pem;
  ssl_certificate_key /etc/letsencrypt/live/npm-6/privkey.pem;

  # ❌ include conf.d/include/assets.conf;  <-- 删除这行

  include conf.d/include/block-exploits.conf;
  # ... rest of config ...
}
```

### Step 3: 测试 nginx 配置

```bash
docker exec nginx-proxy-manager nginx -t
# 应输出: "syntax is ok" + "test is successful"
```

### Step 4: reload nginx (不重启容器)

```bash
docker exec nginx-proxy-manager nginx -s reload
```

或重启用容器:
```bash
docker restart nginx-proxy-manager
```

### Step 5: 清 public-cache

```bash
docker exec nginx-proxy-manager rm -rf /data/nginx/cache/public-cache
# 容器内可能路径不同:  ls /data/nginx/cache/ 看实际目录
```

### Step 6: 浏览器 hard refresh

```bash
# 用户操作: DevTools → Network 勾 "Disable cache" + Ctrl+Shift+R
# 或: 无痕模式 Ctrl+Shift+N
```

## 替代: 保留 assets.conf 但加 no-store

如果某些静态资源**确实需要** cache (生产环境), 不要全删. 在 `location /` 加 no-store 强制 HTML 不 cache:

```nginx
location / {
    # rbac-roles-module 2026-09-23: 防缓存 HTML + 防止 vite dev HMR 旧 build 引用
    add_header Cache-Control "no-store, no-cache, must-revalidate, proxy-revalidate" always;
    add_header Pragma "no-cache" always;
    add_header Expires "0" always;
    
    include conf.d/include/proxy.conf;
}
```

但 `assets.conf` 的 `location ~* \.js$` 仍会劫持 JS chunk — vite dev 模式不需要此 cache, **dev 环境务必全删**.

## 生产 vs Dev

| 环境 | assets.conf 是否保留 |
|---|---|
| **Dev** (vite dev 50998) | ❌ 删 (HMR 需要每次都新 HTML + JS) |
| **Prod** (vite build → nginx serve dist) | ✅ 保留 (content-hash 文件名, 一年 cache 也无害) |

**dev + docker nginx-proxy-manager 反代组合** = 必有 cache 冲突, 务必删 assets.conf.
