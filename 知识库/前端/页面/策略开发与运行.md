## 对应代码路径
- `client/src/views/ScriptDev.vue`（脚本开发）

## 功能概述
ScriptDev：Python 策略脚本在线编辑（列表/新建/编辑/公开开关/审计记录）。ScriptTask：策略任务运行台（纯回测、无实盘；创建回测任务、批次管理、实时进度、结果查看；他人公开策略只读精简，无回测/批次入口）。

## 核心实现

### ScriptDev 关键点
- **新建脚本**：点击"新建脚本"按钮 → 调 `POST /api/script-strategy/scripts/new` → 后端自动命名 `new_strategy`（重名递增 `new_strategy01`/`02`…）+ 用默认模板创建 → 返回创建结果 → 前端刷新列表并选中。不等用户手动保存。
- 脚本保存走 `POST/PUT /api/script-strategy/scripts`，带版本与审计（strategy_script_audit）
- **可见性开关**：编辑器表单 `el-switch`（公开/私有）绑 `form.is_public`，随保存提交（`_formToPayload` 带 `is_public`）；owner/admin 可改，他人公开脚本只读（`:disabled="isReadonly"`）
- 编辑公开脚本受 owner 限制

### ScriptTask 关键流程
```text
创建回测任务（BacktestForm：script 参数 + 标的 + 回测区间）
  → POST /script-strategy/strategies/{id}/backtest  (立即 202 返回, 不等执行)
  → 后端批量建 N 行 task (status='queued') + 转发 strategy_exec /internal/run-batch
  → strategy_exec worker 池 FIFO 有界并发领任务跑回测 + 堵塞自愈 (change 2026-08-30)
  → 任务状态经 WS task_progress_update 实时推 (ws_dispatch._onTaskProgress → wsStore.lastTaskProgress)
  → 页面：属于当前批次 → 节流刷新任务表格 + 就地更新详情进度/状态
```
- **提交立即返回**：POST 建 queued 行即 202（批量 INSERT + to_thread 不阻塞后端），前端不等执行；逐任务状态由 WS/轮询驱动。512 组合大扫描不再吃满前端 15s axios 超时（2026-08-30 sweep-worker-queue）。
- update_strategy 响应不含 script → 保留现有 script（否则 schema 清空回测被挡）
- 重测守卫：批次内无 running/queued 任务才允许

### 进度可视化 + trades 行可展开 + 轮询 fallback（2026-08-29）

- **进度环**：`BatchTasksTable` 行 status=running 时显示 `<el-progress type="circle">` 圆环 + bar/total 文字。进度数据走 `taskProgressMap`（Vue reactive Map<task_id, progress>），ws 推过来时整体替换触发更新。详见 `openspec/specs/frontend/spec.md` REQ-FE-546。
- **trades 行可展开**：`TaskDetail.vue` 交易明细 tab 加 `type="expand"`，展开行按 `stime_side` key 关联 `signal_log` 显示 msg / indicators / state.position / state.cash / trace_id / price_type。列头加 `<el-tooltip :show-after="500">` 说明含义。
- **轮询 fallback**：`_hasActiveTask` computed 监控当前 batch 有 queued/running → 启 3s 周期 `loadBatches + loadBatchTasks`；全 finished/failed 后停。`onBeforeUnmount` 清 timer。

### Stale-queued 视觉标记 + admin 端点（2026-08-29）

- **判定**：task 满足全部 4 条件才算 stale — `status==='queued'` && `!started_at` && (`!progress` 或 `progress.phase==='queued'`) && `(now-created_at) >= 24h`。
- **视觉**：`BatchTasksTable` 行 stale 时加灰色背景（`.bf-row-stale`）+ 状态列追加 `<el-tag type="warning">已超时</el-tag>`；行 hover tooltip 显示「卡 N 小时，建议重测或联系 admin」。
- **过滤**：表格顶部 `<el-checkbox v-model="showStaleOnly">只看超时任务</el-checkbox>`；勾选后只显示 stale 行（`filteredTasks = tasks.filter(isStaleQueued)`）。
- **Banner**：批次卡片顶部 `<el-alert type="warning" show-icon :closable="true">` 显示「批次内 N 个任务卡 queued > 24h，建议重测或联系 admin」+ description「最早一个已卡 N 小时」；可关闭，session 内不重显。
- **与 worker 队列关系（2026-08-30）**：正常跑批时 worker 池会消费 queued 任务，卡死任务由 worker 超时自愈（回 queued 重跑 / 超限 failed），stale 场景大幅减少；stale 标记主要兜底 **strategy_exec 进程停机/崩溃** 导致 task 一直没人领的情况（worker 池是每次触发临时起、内存态，进程重启后**不会**自动续跑历史批次的 queued 任务，需重测/重新提交，若卡 24h 才显 stale 提示）。
- **Admin 端点**：`GET /api/script-strategy/strategies/{strategy_id}/stale-queued?threshold_hours=24`（admin-only，非 admin 返 403），返 `{strategy_id, stale_count, stale_tasks: [{task_id, batch_no, age_min, created_at}]}`。详见 `openspec/specs/frontend/spec.md` REQ-FE-546 § Scenario: 后端 stale-queued 查询。
- **数据安全**：纯前端派生标记 + 只读 SQL，**不动** MySQL 任何表/列/行；用户硬规则 2026-08-27: 不 drop/truncate/delete/rebuild。

### 回测/实盘引擎
实际执行在独立服务 strategy_exec（Backtrader），见 `知识库/策略服务/`。前端只做任务管理与进度展示。
