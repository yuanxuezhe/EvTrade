# 缓存查看器（Cache 四页）

## 对应代码路径
- `client/src/views/CacheAsset.vue`、`CachePositions.vue`、`CacheOrders.vue`、`CacheTrades.vue`（均 admin）
- `client/src/components/DataTableView.vue`
- `client/src/stores/holdings_idb.js`（loadAllOrders/loadAllTrades/loadAllPositions）、`utils/tableColumns.js`

## 功能概述
admin-only 的前端 IndexedDB 四张业务表（asset/positions/orders/trades）CRUD 查看器：查看本地缓存原始数据、按交易日过滤、清理缓存，用于排查"前端显示与后端不一致"问题。

## 文件清单
| 代码文件 | 作用 |
|----------|------|
| `CacheAsset.vue` | 资产查看/编辑：直接读写 holdings store 的 cachedAsset（CacheAsset.vue 编辑器经 asset store 双向桥写回），非 IDB 直读 |
| `CachePositions.vue` | IDB positions 表查看（holdings_idb.loadAllPositions）+ admin 调平 dialog（api.adjustPosition） |
| `CacheOrders.vue` | IDB orders 表查看（holdings_idb.loadAllOrders），trd_date 可选过滤器 |
| `CacheTrades.vue` | IDB trades 表查看（holdings_idb.loadAllTrades），trd_date 可选过滤器 |
| `DataTableView.vue` | 通用数据表格（列配置 tableColumns.js COL、排序/前端分页） |

注：`components/CacheTableView.vue` 目前无任何页面引用（遗留组件）。

## 核心实现

### 数据来源
- positions/orders/trades 三页直接读浏览器 IndexedDB（经 stores/holdings_idb.js 的 loadAllXxx），不经后端 API
- asset 页例外：读 holdings.cachedAsset（内存单源），编辑写回后由 holdings 持久化
- 过滤为页面内 trd_date 查询条件（DataTableView 内部分页）

### 用途定位
- orders 启动拉全量缓存（all=true），本查看器是核对缓存与 DB 差异的诊断工具
- 清空操作只影响本机浏览器缓存，不动后端

## 依赖关系
- 上游：stores/holdings_idb.js、stores/holdings.js（asset 页）、api（CachePositions 调平）
- 下游：无

## 修改指南
- 新增业务表缓存时同步加对应 Cache 页 + 路由（requiresAdmin）
- 列展示改 tableColumns.js，勿在各页重复定义
