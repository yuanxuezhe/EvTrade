# T0 任务管理

## 对应代码路径

- `server/api/t0_tasks.py` — T0 任务 REST 端点（10 个）
- `server/services/t0/tasks.py` — 核心业务（~800 行）
- `server/tables/t0_tasks.py` — t0_tasks 表（12 字段）

## 功能概述

T0 做T任务的全生命周期管理：创建（绑定底仓 base_volume 与系数 coefficient）→ 日常平衡（balance_task 把当日做T单挂到任务）→ 收盘对平（close_task）→ 归档（archive）。状态机：`active ↔ closed → archived`，archived 不可硬删（保留历史审计）。

## 核心实现

### t0_tasks 表（tables/t0_tasks.py）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | int | 自增 PK |
| user_id | int | 归属 |
| stock_code | varchar(16) | 标的 |
| base_volume | int | 底仓股数 |
| target_volume | int | 目标持仓（平衡基准） |
| coefficient | float | 做T系数 |
| status | varchar(16) | active / closed / archived |
| note | varchar(255) | 备注 |
| created_trd_date | varchar(8) | 创建交易日 |

### create_task（services/t0/tasks.py）

校验 stock_code 持仓存在（positions 表）→ base_volume 不超过 vol → 写入 status='active'，target_volume = base_volume。

### balance_task（7 步，每日收盘对账）

```
1. 取任务（active 状态校验）
2. 拉当日该 stock_code 的 T0 委托单（orders.strategy_type=1 + task_id）
3. 排除 CANCEL: 撤单行
4. 计算当日买卖净额 → 更新 target_volume（base_volume 滚动）
5. 校验与柜台实际持仓偏差（超出容差告警）
6. 写回 t0_tasks
7. 返回平衡结果摘要
```

### close_task / archive

- `close_task`：收盘对平校验（当日净敞口为 0 或强制平）→ status='closed'，closed_at 时间戳。
- `archive`：closed → archived；archived 行**不可硬删**（DELETE 端点对 archived 返回 409）。

### aggregate_task_stats（v62 委托口径）

- 统计口径用**委托**（orders）而非成交（trades），因为做T当日撤单/废单需纳入敞口判断。
- v127.2 `_prefetch_task_stats`：批量预取修复 —— 旧实现 N 个任务 × M 次单查导致列表页 68s 阻塞；改为 `Orders.query_by_in('task_id', task_ids)` 一次拉回内存分组，列表页降到亚秒。

## 依赖关系

## 修改指南

- **状态机扩展**：新增状态需同步 DELETE/close/archive 的状态校验分支与前端状态色。
- **批量查询模式**：任何"列表页逐任务查 orders"的新代码必须走 `query_by_in` 批量预取（v127.2 已踩坑）。
- **撤单排除**：涉及当日盈亏/敞口的计算必须排除 `user_def` 以 `CANCEL:` 开头的委托行（v130.2）。
- **归档不可删**：archived 删除限制是审计要求，不要放宽；清理老数据走归档迁移脚本而非 DELETE 端点。
