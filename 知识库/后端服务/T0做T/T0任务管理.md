# T0 任务管理

## 对应代码路径

- `server/api/t0_tasks.py` — T0 任务 REST 端点（11 个，路由前缀 `/api/t0-tasks`）
- `server/services/t0/tasks.py` — 核心业务（~830 行）
- `server/tables/t0_tasks.py` — t0_tasks 表（12 字段）

## 功能概述

T0 做T任务的全生命周期管理：创建（绑定底仓 base_volume、目标 target_volume 与系数 coefficient）→ 一键配平（balance_task 计算并返回补仓/减仓建议单）→ 关闭（close_task 强制配平回 base_volume）→ 归档（archive）。状态机：`active → closed → archived`；active/closed 可删（archived 视为长期记录不可硬删）。

## 核心实现

### t0_tasks 表（tables/t0_tasks.py）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | int | 自增 PK |
| user_id | int | 归属 |
| stock_code | varchar(16) | 标的 |
| base_volume | int | 底仓股数 |
| target_volume | int | 目标持仓（平衡基准） |
| coefficient | float | 做T系数 |
| status | varchar(16) | active / closed / archived |
| note | varchar(255) | 备注 |
| created_trd_date | varchar(8) | 创建交易日 |

### create_task（services/t0/tasks.py）

校验 base_volume ≥ 0、coefficient ∈ [0,10] → 写入 status='active'，created_trd_date 缺省取激活交易日；target_volume 由请求传入（可为负=净减仓），不做持仓存在性校验。

### balance_task（一键配平，8 步）

```
1. 取任务（active 状态校验）
2. 计算 task 净敞口 task_net_volume（跨日累加，_calc_task_net_volume）
3. 取当前持仓 vol/avl_vol（positions 按 stock_code 单行）
4. 目标仓位 = base_volume + target_volume；缺口 gap = 目标 - 当前持仓
5. 应用配平系数：balanced_volume = round(gap × coefficient)
6. 整手（买向下/卖向上取整，卖不超可用 avl_vol）
7. 资金校验（买单：配平成本 ≤ assets.cash，否则 ValueError）
8. 持仓校验（卖单不超可用）→ 返回 {action: BUY/SELL/NONE, volume, price, reason, ...} 建议单
```

注意：balance_task 只**返回**建议单，不落库、不下单、不写 t0_tasks。

### close_task / archive / delete

- `close_task`：临时把 target_volume 置 0 → 调 balance_task 配平回 base_volume（保留底仓）→ 恢复 target_volume → status='closed' + closed_at 时间戳。
- `archive`：仅 closed → archived；其他状态 ValueError → 409。
- `delete_task`：active/closed 可删（误建可立即删）；**archived 不可硬删**（ValueError → 409，保留长期记录）；删除时关联 orders.task_id 置 NULL（保留审计）。

### aggregate_task_stats（委托口径）

- 统计口径用**委托**（orders）而非成交（trades）：已成交部分用委托价 Order.price，未成交部分买入按 ask1、卖出按 bid1 配平（(avg_sell - avg_buy) × paired_vol - fee - tax）。
- 撤单类 status（51/52/53/54）的委托不参与计算。
- `_prefetch_task_stats`：批量预取 —— 逐任务单查会导致列表页阻塞（曾达 68s）；改为 `Orders.query_by_in('task_id', task_ids)` 一次拉回内存分组，列表页降到亚秒。

## 修改指南

- **状态机扩展**：新增状态需同步 DELETE/close/archive 的状态校验分支与前端状态色。
- **批量查询模式**：任何"列表页逐任务查 orders"的新代码必须走 `query_by_in` 批量预取。
- **撤单排除**：涉及当日盈亏/敞口的计算必须排除 `user_def` 以 `CANCEL:` 开头的委托行。
- **归档不可删**：archived 删除限制是审计要求，不要放宽；清理老数据走归档迁移脚本而非 DELETE 端点。
