# T0 统计与聚合

## 对应代码路径

- `server/api/t0_stats.py` — 单股票 T0 统计端点
- `server/api/t0_aggregate.py` — 敞口/聚合端点
- `server/services/t0/aggregators.py` — 聚合算法核心
- `server/services/t0/aggregate_api.py` — facade 再导出
- `server/services/t0/tasks.py` — `_prefetch_task_stats`（批量预取）

## 功能概述

T0 做T的统计视图层：按股票统计当日做T盈亏（已实现/浮动）、净敞口、聚合汇总（按股票/按天/总览）。口径基于当日 trades（成交）为主，按 `user_def` 标签过滤做T单（`t0_only` / `user_def` 参数；'T0' 字面量 + 所有 type='t0' 策略单的 user_def），并排除 `CANCEL:` 撤单代行行（防撤单虚增 day_pnl）。

## 文件清单

| 端点 | 说明 |
|---|---|
| GET /api/orders/t0-stats/{stock_code} | 单股票当日 T0 统计（T0StatsOut 15 字段） |
| GET /api/orders/t0-history/{stock_code} | 单股票 T0 历史日序列 |
| GET /api/orders/t0-exposure | 当前净敞口（T0ExposureOut） |
| GET /api/orders/t0-aggregate | 聚合汇总（T0AggregateOut） |

## 核心实现

### T0StatsOut（15 字段，t0_stats.py）

关键字段口径（当日买卖量按**成交** trades 统计）：

| 字段 | 计算式 |
|---|---|
| today_buy_volume / today_sell_volume | 当日做T买/卖成交量 |
| today_buy_amount / today_sell_amount | 对应金额 |
| realized_pnl | `(avg_sell - cost_basis) * sell_vol - commission - stamp_tax`（calc_realized_pnl） |
| unrealized_pnl | `(avg_sell - cost_basis) * position_volume`（浮动；当日无卖出时保守返回 0，前端用行情现价） |
| cost_basis / position_volume / position_cost_total | 持仓成本价 / 持仓量 / 持仓成本总额（positions 表） |
| total_pnl | realized + unrealized |
| order_count / trade_count / open_order_count | 委托/成交/在途委托（status 48/49/50）计数 |

### aggregators.py 核心函数

```
calc_net_exposure(orders, trades)   单标的敞口 = 买单量 - 卖单量（按 trades，废单 status=55 不计）→ (net_vol, buy_vol, sell_vol, buy_amt, sell_amt)
apply_user_def_filter(orders, trades, user_def, db=None)
                                    过滤 user_def 标签 + 永久排除 user_def 'CANCEL:' 撤单代行及其 trades → (f_orders, f_trades)
aggregate_by_stock(trades, orders, positions, fee_cfg)   按股票分组 → 每股统计 dict
aggregate_by_day(trades, positions, fee_cfg)             按天分组 → 日序列
aggregate_summary(by_day, by_stock, orders)              总览（总买卖额/总费用/胜率/回报率）
resolve_t0_user_defs(db, user_def)  解析标签（'T0' → {'T0'} ∪ type='t0' 策略 id 集合）
```

### aggregate_api.py

纯 facade：`from .aggregators import *` 再导出，供 api 层与旧调用方稳定引用。改动 aggregators 函数签名时无需改 api 层 import。

### 数据装配模式（性能关键）

- 单股票统计（t0-stats）：`Orders.query_by('trd_date', trd)` / `Trades.query_by('trd_date', trd)` → 内存过滤 stock_code（t0_only 时再按 resolve_t0_user_defs 过滤）。
- 敞口（t0-exposure）：`Orders/Trades.query_by('trd_date', trd)` + `Positions.query_all()` → apply_user_def_filter → aggregate_by_stock。
- 跨期聚合（t0-aggregate）：`Orders/Trades.query_all()` 全表 → 内存过滤 trd_date ≥ cutoff（days 参数）→ 三视角聚合，by_day 附 cum_pnl 累计盈亏。
- 历史曲线（t0-history）：`Trades.query_all()` + 内存区间过滤（近 days*2 自然日）。

## 修改指南

- **口径变更**：day_pnl/unrealized 的计算式集中在 pnl.py + t0_stats.py 装配处，改口径两处同步；不要在 aggregators 里重复实现盈亏公式。
- **新统计维度**：加在 aggregators 的 aggregate_* 函数并保持纯函数（输入 rows 输出 dict），端点层只做取数与 schema 装配。
- **过滤规则**：`apply_user_def_filter` 是所有统计的入口过滤器，任何新统计端点必须先过它。
- **性能红线**：禁止在循环内逐股票 `query_by`；多股票场景一律 query_by_in 批量取。
