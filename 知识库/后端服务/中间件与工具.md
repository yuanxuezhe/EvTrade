# 中间件与工具

## 对应代码路径

- `server/middleware/request_logging.py`（RequestLoggingMiddleware）
- `server/utils/logflow.py`（log_interaction 统一交互日志）
- `server/utils/file_logging.py`（setup_file_logging）
- `server/utils/time.py`（时间工具）
- `server/enums/trading.py`（交易枚举）、`server/constants.py`（兼容垫片）

## 功能概述

中间件与工具层：HTTP 请求/响应交互日志（REQ-LOG-003，[front->svc]/[front<-svc] 格式、trace 配对、敏感头脱敏、body 截断）；logflow 四方向交互日志入口；文件日志轮转；时间戳统一格式；交易协议枚举。均为失败安全设计——日志功能异常绝不影响业务。

## 核心实现

### RequestLoggingMiddleware（REQ-LOG-003/004/005）
- `dispatch(request, call_next)` 流程：
  1. 跳过 `/api/health`、`/ws/` 前缀（`_SKIP_PATH_PREFIXES`）。
  2. trace_id = `X-Trace-Id` header（优先）或 `uuid4().hex[:8]`，挂 `request.state.trace_id`。
  3. 读 body（json 解析失败降级原串），记 `[front->svc][trace=X] METHOD /path`，data 含 query/body/headers。
  4. **body 回放**：`await request.body()` 会耗尽流，重新构造 `Request(scope, receive_replay)` 注入一次性 receive，否则下游 Pydantic 解析拿不到。
  5. `call_next` 计时；异常记 `[front<-svc] ERROR ... (exc)` 后 re-raise。
  6. 读响应 body_iterator 后重新包装 StarletteResponse（消费后回填）；记 `[front<-svc] <status> METHOD /path (elapsed ms)`，status 5xx→error / 4xx→warning / 其他 info；响应头加 `X-Trace-Id`。
- 敏感头 `_SENSITIVE_HEADERS = {authorization, cookie, x-api-key, x-auth-token}`：值仅保留前 8 字符 + `***`。
- 截断：请求侧 data 由 logflow 按 4KB 截；响应 >8192 字符时截到 1024 + `[truncated]`。

### logflow.log_interaction
```python
log_interaction(direction, summary, *, data=None, elapsed_ms=None,
                level="info", trace_id=None)
```
- 方向常量：`DIR_FRONT_TO_SVC="front->svc"`、`DIR_SVC_TO_RPC="svc->rpc"`、`DIR_SVC_FROM_RPC="svc<-rpc"`、`DIR_SVC_TO_FRONT="front<-svc"`。
- 输出行：`[ts][level][direction][trace=XXX] summary (Xms)`，data 每 key 一行缩进（多行值再缩进）；截断上限 HTTP 4KB / RPC 2KB（按字节，追加 `[truncated, total=N bytes]`）。
- logger 名 `server.interaction`；内部 try/except 全吞（print 兜底），不影响业务。

### setup_file_logging
```python
setup_file_logging(log_dir=None, prefix="server", level=INFO, backup_days=6) -> str
```
- 默认目录 `server/logs/`；文件 `server.log`，midnight 本地时区轮转，suffix `%Y-%m-%d`（归档形如 server-<YYYY-MM-DD>），backupCount=6 含当天共 7 天。
- 幂等：handler 带 `_evtrade_file_log` 标记防重复挂；目录创建失败仅 warning 不阻塞启动。
- 文件格式 `[asctime][levelname][name] message`（比 console 多 logger 名便于 grep）。

### utils/time.py
- `TS_FMT = "%Y-%m-%d %H:%M:%S.%f"` 截 3 位毫秒（23 字符），全系统统一。
- `format_ts(dt=None, tz='local')`：业务时间戳 local、系统时间戳 utc。
- `parse_broker_ts(s, trd_date='', tz='local')`：broker 多种格式 → 标准格式。
- `_utcnow()`：naive UTC（DB 列无 tz）；`format_db_dt(dt)`：DB DateTime → 标准串。

### enums/trading.py
- `PriceType`：与 xtconstant 1:1 对齐 —— FIX_PRICE=0 限价 / LATEST_PRICE=1 最新价 / MARKET_PEER_PRICE_FIRST=2 市价（对手方最优吃档 1）；`label(code)` 中文、`default()=0`。旧码点 5/11/14/44 由迁移 `2026-07-15-remap-price-type.py` 映射（11/14→0、5→1、44→2）。
- `OrderType`：BUY="23" / SELL="24"（柜台协议码）。
- `Direction`：BUY/"SELL" 字符串 + `opposite()`。
- `constants.py` 仅 re-export 三者（不再有 OrderStatus，状态推断/文案见 server/repo/orders.py）。

## 修改指南
- 新增跳过日志的路径：改 `_SKIP_PATH_PREFIXES`（前缀匹配）。
- 新增脱敏头：加进 `_SENSITIVE_HEADERS`（小写 key）。
- 改日志保留天数：`file_logging.BACKUP_DAYS` 或调 setup_file_logging(backup_days=)。
- 交互日志一律走 log_interaction，勿手拼 `[front->svc]` 字符串；记得传 trace_id 保证配对。
- 新枚举值必须与柜台 xtconstant 协议对齐，并考虑存量数据迁移脚本。
