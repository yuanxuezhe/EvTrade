# 下单与撤单

## 对应代码路径

- `server/api/orders/place.py` — 下单入口（两阶段）
- `server/api/orders/cancel.py` — 撤单入口
- `server/api/orders/query.py` — 委托查询（GET / 与 /history，纯 DB 读路径）
- `server/api/orders/schemas.py` — 请求/响应 Pydantic 模型
- `server/services/guards.py` — 交易日/交易时段/交易员屏障
- `server/tables/orders.py` — orders 表模型（23 字段，复合主键 `trd_date + order_no`）

## 功能概述

交易核心的写入路径。下单采用**两阶段架构**：阶段 A 立即落库 orders 表并返回 HTTP 响应（status=48 未报），阶段 B 通过 `asyncio.create_task(_submit_rpc_async)` 异步调 QMT 柜台 RPC 报单（应答 ack 不驱动落库，真实状态由 broker 异步 ord_cfm 推送/transport 层接管，仅 RPC 异常时兜底写 57）。撤单走本地代理行流程：校验原单 → 插入撤单行 → RPC 撤单 → 回写撤单行状态 → 推送前端。

## 核心实现

### 下单两阶段（place.py）

```
阶段 A（同步，HTTP 请求线程内）:
1. 屏障校验: require_trader / require_trading_day / require_trading_session / require_rpc_ok
   + stktype 可交易校验 + 价格按 stock.scale 四舍五入
2. 解析 PlaceOrderRequest → T0 配平 calc_t0_volume → 生成 order_no（当日自增）
3. insert_pending_order({status: "48", ...}) 落库（server/repo/orders.py 封装）
4. WS 推 status=48（_broadcast_order_cfm）+ 返回 PlaceOrderResponse（含 fee_breakdown / t0_adjusted_volume）

阶段 B（异步，asyncio.create_task）:
5. _submit_rpc_async() → 调 ord_stk RPC，携带 msgid_meta
6. ack.code 不驱动落库 — code=0 等 broker 异步 ord_cfm 推送真实状态；
   code!=0 由 transport 层按 msgid 反查写废单；仅 RPC 异常（超时等）兜底写 status=57 + status_msg
7. 通过 _broadcast_order_cfm 推前端（type='ord_cfm'）
```

- `msgid_meta` 机制：RPC 报文号与 order_no 的映射缓存，用于推送回报匹配。
- 延迟导入 RPClient（late import），便于测试 monkeypatch。

### PlaceOrderRequest 字段（schemas.py）

| 字段 | 类型 | 说明 |
|---|---|---|
| stock_code | str | 证券代码，如 600519.SH |
| order_type | str | "23" 买 / "24" 卖 |
| price_type | int | 11 限价（默认）/ 44 市价（FIX） |
| price | float | 限价单价格 |
| volume | int | 委托数量（股） |
| t0_coefficient | float | T0 配平系数，默认 1.0 |
| strategy_type | int | 0 普通单 / 1 快速做T / 2 策略下单 |
| task_id | int? | T0 任务 ID（做T单归因，需校验归属与 active） |
| user_def | str | 用户自定义备注（撤单行前缀 CANCEL:） |

### OrderOut 响应（19 字段）

`trd_date, order_no, order_id, user_def, stock_code, order_type, price_type, price, volume, traded_volume, traded_amount, avg_price, cancelled_volume, order_flag, status, status_msg, order_time, raw_id, task_id, strategy_type`（由 `_to_order_out(row)` 统一装配）。

### 委托状态码

| status | 含义 |
|---|---|
| 48 | 未报（阶段 A 落库） |
| 49 | 已报待（RPC 已发） |
| 50 | 已报（柜台确认） |
| 51 | 部成待 |
| 52/53/54 | 撤单类（54 已撤） |
| 55 | 部成 |
| 57 | 废单 |

### 撤单流程（cancel.py）

1. `Orders.query_one(trd_date, order_no)` 校验原单存在、可撤（status ∈ 50 已报 / 55 部成）且 broker 已回报 order_id
2. `insert_cancel_row`：插入撤单委托行（order_flag=1），`raw_id` 复用原单 order_no，`user_def` 前缀 `CANCEL:`
3. RPC 撤单调用（rpc_cancel_order，try/except 捕获网络异常）
4. 回写**撤单行**状态：成功 → cancel_row status=54（已撤）+ 抹平原单 cancelled_volume=volume + 插入撤单成交 Trades 行（trade_type=1 撤单成交标记）；失败/异常 → cancel_row status=57（废单，审计保留）；`_safe_status_msg` 截断消息到 250 字符防越界
5. WS 推送：order_update（撤单行）+ 成功时 trade_update（撤单成交）

### 屏障（guards.py）

| 屏障 | 抛出错误码 | HTTP |
|---|---|---|
| require_trading_day | TRADING_DAY_NOT_INIT | 503 |
| require_trading_session | OUTSIDE_TRADING_SESSION | 503 |
| require_trader / require_admin | FORBIDDEN | 403 |

下单/撤单端点还统一挂 `require_rpc_ok`（server/api/deps.py）：RPC 健康检查不通过时在路由层直接拦截。

`resolve_default_trd_date`：优先取激活交易日（sys_status 单行 id=1）；未激活则依次兜底取 orders / trades / reconcile_report 三表的 `MAX(trd_date)`；再兜底今日。

### orders 表关键字段（tables/orders.py）

主键 `(trd_date varchar(8), order_no varchar(8))`。注意 `order_id`（柜台返回的委托编号）非主键，推送回报匹配键是 `(trd_date, order_no)`。

## 依赖关系

```
api/orders/place.py ──→ services/guards.py（屏障）
        │             ──→ tables/orders.py（add_one / update_one）
        │             ──→ services/push/order_broadcast.py（WS 推送）
        └── 阶段B ──→ rpc RPClient（QMT 柜台）
api/orders/cancel.py 同上
signal_consumer（策略引擎）→ 自调用 POST /api/orders/place
```

## 修改指南

- **新增委托来源**（如新策略类型）：在 `PlaceOrderRequest` 增加 strategy_type 枚举值，并同步前端 OrderOut 展示映射；不要复用 task_id 语义。
- **改状态码映射**：状态码是柜台契约（48-57），只读不改；新增状态需同时更新 push/ord.py 的匹配逻辑与前端状态字典。
- **改下单字段**：orders 表是 tables-codegen 自动生成的，先改 DDL 再重新生成 `server/tables/orders.py`，再同步 `_to_order_out`。
- **测试钩子**：阶段 B 用 late import 引 RPClient，monkeypatch `place._submit_rpc_async` 或 RPClient 方法即可离线测试。
- **撤单行识别**：所有依赖订单列表的统计（如 T0 day_pnl）必须排除 `user_def LIKE 'CANCEL:%'` 的行。
