# 成交查询

## 对应代码路径

- `server/api/orders/query.py` — 委托查询
- `server/api/trades.py` — 成交查询
- `server/api/orders/schemas.py` — OrderOut（复用）
- `server/tables/orders.py` — orders 表
- `server/tables/trades.py` — trades 表（11 字段，主键 `(trd_date, order_no, trade_id)`）

## 功能概述

交易核心的只读查询路径。委托查询支持当日/历史区间/all 三种模式，成交查询按 `trade_time DESC + trade_id DESC` 双级排序保证同秒成交顺序稳定。两者均走 `Orders.query_all() + 内存过滤` 模式，无 ORM session 依赖。

## 文件清单

| 文件 | 职责 |
|---|---|
| `server/api/orders/query.py` | GET /api/orders（当日/区间/全部） |
| `server/api/trades.py` | GET /api/trades |
| `server/api/orders/schemas.py` | OrderOut + _to_order_out |

## 核心实现

### GET /api/orders（query.py）

```
参数优先级: all=true > start_date/end_date 区间 > trd_date 单日（缺省=激活日）
统一模式: Orders.query_all() 全表 → _filter_orders 内存过滤 → order_time 倒序 → offset/limit 切片
- all=true: 跳过日期过滤，limit 上限放宽到 10000（默认 2000）
- 区间模式: start_date <= trd_date <= end_date（内存过滤）
- 单日模式: trd_date 等值（内存过滤）
- 可选 stock_code / status 过滤；无 task_id 参数（前端缓存层过滤）
```

`_filter_orders(rows, stock_code=None, ...)`：统一过滤 helper，空参数直通。

### GET /api/trades（trades.py）

- 统一 `Trades.query_all()` 全表 → 内存过滤（all=true / 区间 / 单日三模式，语义同 orders）。
- 排序：`trade_time DESC`，同时间再按 `trade_id DESC`（二级排序，保证同秒多笔成交顺序确定）。
- limit：all=true 模式默认 2000（上限 10000）；单日/区间模式截 500。

### TradeOut 字段（10 字段）

`trd_date, order_no, trade_id, stock_code, order_type, price, volume, amount, trade_time, trade_type`

- `trade_type`（int）：成交类型标识，0=普通成交 / 1=撤单成交（cancel.py 合成的本地代理撤单成交行）。
- 成交行由 push/trd.py 的 `handle_trd_cfm` 写入，查询侧只读。

### trades 表（tables/trades.py）

| 字段 | 类型 | 说明 |
|---|---|---|
| trd_date | varchar(8) | 交易日期 YYYYMMDD（PK1） |
| order_no | varchar(8) | 委托号（PK2，关联 orders） |
| trade_id | varchar(64) | 柜台成交编号（PK3） |
| trade_time | varchar(23) | 成交时间（排序键） |
| order_type | varchar(2) | 23 买 / 24 卖 |

## 依赖关系

```
api/orders/query.py ──→ tables/orders.py (query_all + 内存过滤)
api/trades.py       ──→ tables/trades.py  (query_all + 内存过滤)
前端: 当日委托/成交页、T0统计页（t0_stats 复用 Trades 读取）
写入方: services/push/trd.py handle_trd_cfm + api/orders/cancel.py（撤单成交行）（本模块只读）
```

## 修改指南

- **加过滤条件**：统一加在 `_filter_orders`，不要在端点内散落 if；trades 如需过滤照搬该模式。
- **性能**：`query_all()` 是全表拖回内存，all 模式仅适合单账户日终数据量；若未来量级增大，应在 tables 层加下推过滤（WHERE）而非内存过滤。
- **排序变更**：trades 双级排序是前端成交列表正确性的前提，改排序前确认撤单重排场景。
- **新字段**：trades 表改动走 DDL → tables-codegen 重新生成 → 同步 TradeOut。
