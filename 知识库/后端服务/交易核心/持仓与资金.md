# 持仓与资金

## 对应代码路径

- `server/api/positions.py` — 持仓查询 + 装配调整
- `server/api/holdings.py` — 精简持仓视图
- `server/api/asset.py` — 资产查询
- `server/api/asset_adjust.py` — 资产手工调整（admin）
- `server/api/position_adjust.py` — 持仓手工调整（admin）
- `server/tables/positions.py` — positions 表（8 字段，主键 stock_code）
- `server/tables/assets.py` — assets 表（9 字段，单行 id=1）

## 功能概述

账户状态视图层。positions 提供完整持仓（9 字段），holdings 是共享 positions 表的精简视图（6 字段），asset 是单行资产表。市值计算策略：后端只存成本口径 `market_value = cost_price * vol`，实时市值由前端用行情快照重算。手工调整端点（admin 鉴权）用于修正柜台对账差异。

## 文件清单

| 文件 | 端点 | 职责 |
|---|---|---|
| `server/api/positions.py` | GET /api/positions | 完整持仓列表（PositionOut 9 字段） |
| `server/api/positions.py` | PUT /api/positions/{stock_code}/adjust | 持仓修正 |
| `server/api/holdings.py` | GET /api/holdings | HoldingItem 6 字段精简视图 |
| `server/api/asset.py` | GET /api/asset | AssetOut 资产 |
| `server/api/asset_adjust.py` | PUT /api/asset/adjust | 资产修正（admin） |

## 核心实现

### PositionOut（9 字段）

`stock_code, stock_name, last_vol, avl_vol, vol, cost_price, market_value, synced_at, synced_from`

- `market_value = cost_price * vol`（成本口径快照，前端拿 last_price 实时重算浮盈）。
- `avl_vol`：可用数量（今日买入不可卖部分已扣减）；`last_vol`：昨日持仓。

### HoldingItem（6 字段）

`stock_code, last_vol, vol, avl_vol, cost_price, market_value` — 供首页/下单页选股用（market_value 仍为成本口径）。

### AssetOut（assets 表单行，`Assets.query_one(id=1)`）

| 字段 | 说明 |
|---|---|
| cash | 现金 |
| available | 可用资金 |
| frozen_cash | 冻结资金 |
| market_value | 持仓市值（成本口径） |
| total_asset | 总资产 |
| last_asset | 期初总资产（当日盈亏基准） |
| synced_at / synced_from | 同步时间与来源（rpc_sync / manual） |

asset.py 还提供 `GET /api/asset/rpc-status`：返回 rpc_health 的 RPC 通信健康状态。

### 资产调整（asset_adjust.py）

```
PUT /api/asset/adjust  (require_admin)
body: {delta_cash?: float, delta_total_asset?: float, reason?: str}
1. _reject_nan 校验（拒绝 NaN）；两个 delta 至少传一个（否则 422）
2. 读 assets id=1（无行则初始化全零）→ 原子累加: cash += delta_cash, total_asset += delta_total_asset
3. synced_from = "manual", 写回 update；reason 仅入 log 不入库
```

### 持仓调整（position_adjust.py）

```
PUT /api/positions/{stock_code}/adjust  (require_admin)
body: {delta_vol?: int, delta_avl_vol?: int, reason?: str}
- 不存在该股票 → 404 POSITION_NOT_FOUND（不自动新建）
- delta 语义与资产调整一致（增量修正而非覆盖）；cost_price / last_vol 不动（仅 do_reconcile 写）
```

### positions 表字段

`stock_code(PK), stock_name, last_vol, avl_vol, vol, cost_price, synced_at, synced_from(varchar(16))`

`synced_from` 取值：`pos_push`（柜台推送，权威源）/ `push_partial`（push/trd.py 成交增量）/ `rpc_reconcile`（日初对账）/ `manual`（手工）。

## 依赖关系

```
api/positions.py ──→ tables/positions.py
api/holdings.py  ──→ tables/positions.py（共享表）
api/asset.py     ──→ tables/assets.py + services/rpc_health.py（rpc-status）
写入方: positions → services/push/pos.py handle_pos_push（权威源）
                 + push/trd.py（成交增量 push_partial）
                 + init reconcile（suppress_pos_push 抑制期间, rpc_reconcile）
        assets   → services/rpc_health.py 定时同步（synced_from=rpc_sync）
读取方: 前端持仓页 / T0 敞口计算（t0_aggregate 读 positions.vol）
```

## 修改指南

- **市值口径**：不要把实时行情耦合进 positions 后端；保持"后端成本快照 + 前端实时重算"分工。
- **加资产字段**：assets 表加列后需同步 asset_adjust 的增量逻辑与 init 对账写入点。
- **调整端点安全**：adjust 类端点必须挂 `require_admin`；新增调整维度沿用 delta 增量语义，避免全量覆盖误操作。
- **注意**：positions 的权威更新方是 `handle_pos_push`；若手工调整与推送并发，推送后写会覆盖手工值，调整后如需持久应同时核对柜台。
