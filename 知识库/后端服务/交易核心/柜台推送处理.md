# 柜台推送处理

## 对应代码路径

- `server/services/push/dispatcher.py` — 推送编排入口
- `server/services/push/handlers.py` — HANDLERS 注册表
- `server/services/push/ord.py` — 委托确认 ord_cfm
- `server/services/push/trd.py` — 成交确认 trd_cfm
- `server/services/push/pos.py` — 持仓推送 pos_push
- `server/services/push/helpers.py` — 类型转换 + 行转 dict
- `server/services/push/order_broadcast.py` — 统一委托 WS 广播
- `server/services/push/routes.py` — 频道映射
- `server/services/push/run_handlers.py` — 线程池执行器
- `server/services/push/log_helpers.py` — 交互日志（REQ-LOG-003）

## 功能概述

处理 QMT 柜台（xtquant broker）主动推送的回报消息。三类 handler：`ord_cfm`（委托确认）、`trd_cfm`（成交确认）、`pos_push`（持仓变化推送）。注意 xtquant broker **不发** pos_cfm / ast_cfm，持仓由 pos_push 接管、资产由 rpc_health 定时同步（trd_cfm 不动 positions/assets）。回报与本地订单的唯一匹配键是 `(trd_date, order_no)`，不是 order_id。

## 文件清单

| 文件 | 职责 |
|---|---|
| dispatcher.py | `PushDispatcher.dispatch` 编排：解析 → 路由 handler → 广播 |
| handlers.py | `HANDLERS = {ord_cfm, trd_cfm, pos_push}`，`handle_push` 统一入口 |
| ord.py | `handle_ord_cfm`：状态回写 + cancelled_volume 累加 |
| trd.py | `handle_trd_cfm`：写 trades（幂等）；不动 positions/assets |
| pos.py | `handle_pos_push` + `suppress_pos_push` 上下文管理器 |
| helpers.py | `_str/_float/_int/_round_scale` + `_order/_trade/_position_to_out_dict` |
| run_handlers.py | `_run_handle_push`（loop.run_in_executor + db_session） |

## 核心实现

### 推送数据流

```
QMT RPClient 回调 → PushDispatcher.dispatch(pkt, func, msg_type, wire_len)
  ├─ 交互日志（log_helpers._log_push_interaction）
  ├─ channel = routes._PUSH_CHANNEL.get(func)   (未知 func → 跳过不炸)
  ├─ _resolve_active_trd_date_safe() 注入激活交易日 + _iter_push_rows 解析推送行
  ├─ handler 在线程池 run_in_executor 内执行（run_handlers._run_handle_push, 自带 db_session）
  └─ 广播: trd_cfm → _broadcast_trade_cfm（trade_update + order_update）
           其他（ord_cfm/pos_push）→ _broadcast_generic（handler 返回 None 则跳过广播）
WS 频道映射 (routes.py):
  ord_cfm  → channel 'order_update'
  trd_cfm  → channel 'trade_update'
  pos_push → channel 'position_update'
```

### handle_ord_cfm（ord.py）

- 匹配：`(trd_date, order_no)` 唯一键查 Orders；本地无单只记日志不建单。
- `cancelled_volume`：柜台可能分多次推撤单量，**累加**而非覆盖；broker_status 落在撤单类（52/53/54）且未推撤单量时本地兜底抹平到 volume。
- `broker_status`（如 50/54/57）直接写入 orders.status（缺失时兜底 '50'）；status_msg 直接用 broker 推送值（不再本地 _status_msg 兜底）。
- 同时维护 traded_volume（累计）与 traded_price→avg_price/traded_amount；order_volume 变化时覆盖 volume。
- 委托推送**始终**返回广播 payload（`_order_to_out_dict`），由 dispatcher `_broadcast_generic` 推 order_update；`order_broadcast._broadcast_order_cfm` helper 仅被 API 层（place.py/cancel.py）使用。

### handle_trd_cfm（trd.py）

```
1. 写 trades 表（trd_date+order_no+trade_id 主键幂等，已存在则跳过）
2. 不动 Order 的 traded_volume 累计（由 ord_cfm 维护，防双写漂移）
3. 不处理持仓（position 恒为 None）→ 持仓由 pos_push 接管
   （_update_position_vol 函数仍留存但已无调用方，属死代码）
4. 不动 assets（资产由 rpc_health 定时同步）
5. 返回 {trade, order, position=None}，dispatcher 广播 trade_update + order_update
```

### handle_pos_push（pos.py）

- 柜台线格式映射：`volume→vol`、`avl_amt→avl_vol`、`avg_price→cost_price`。
- 全量覆盖 positions 行（柜台是权威源），`synced_from='pos_push'`。
- `suppress_pos_push` context manager：init reconcile 期间抑制 pos_push，防止对账写入被推送覆盖。

### run_handlers.py

- `_run_handle_push`：`loop.run_in_executor`（不阻塞事件循环），线程内开 `db_session`。
- `_resolve_active_trd_date_safe`：推送缺 trd_date 时安全解析当日，失败不抛。

### helpers.py 转换约定

- `_float` / `_int`：坏值返 0.0 / 0；`_round_scale(x, n)` 按柜台精度四舍五入。
- `_order_to_out_dict` / `_trade_to_out_dict` / `_position_to_out_dict`：与 API 层 OrderOut/TradeOut/PositionOut 字段一一对应，保证 WS 推送与 REST 查询同构。

## 依赖关系

```
rpc RPClient 回调 ──→ dispatcher.dispatch
handlers ──→ tables/orders.py、tables/trades.py、tables/positions.py、tables/assets.py
ord.py   ──→ dispatcher 广播（order_broadcast.py 被 api/orders 的 place/cancel 使用）
trd.py   ──→ repo/stocks.py（get_stock_scale）
pos.py   ←─ init reconcile（suppress 协作）
日志: log_helpers._log_push_interaction / _log_push_broadcast（REQ-LOG-003 审计）
```

## 修改指南

- **新增推送类型**：在 `HANDLERS` 注册 + routes.py 补频道映射；dispatcher 对未注册类型自动跳过（既有契约），不要在 dispatcher 里写类型特判。
- **状态累计字段**：cancelled_volume / traded_volume 是累加语义，改动前确认柜台是否重复推送同笔部分量。
- **订单匹配**：只能用 `(trd_date, order_no)` 匹配；order_id 是柜台异步回填的，阶段 A 时为空。
- **持仓写入权**：positions 权威写入方是 pos_push；trd_cfm 里不要恢复直接写 positions 的旧逻辑，否则会出现推废竞态。
- **广播失败**：广播异常必须吞掉记 log（推送处理不能因 WS 断连而 nack 重推，会造成成交重复写入）。
- **线程安全**：handler 跑在线程池，每个任务自带 db_session；不要共享模块级 session。
