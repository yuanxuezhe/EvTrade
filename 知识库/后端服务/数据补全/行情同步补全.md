# 行情同步补全

## 对应代码路径

- `server/api/quote_sync.py`（REST 端点：配置 CRUD + 按日同步）
- `server/services/quote_sync/broker.py`（自包含 broker his_hq 单日多字段客户端）
- `server/services/quote_sync/sync.py`（按日补全核心 + 启动自动增量补全）
- `server/services/quote_sync/manager.py`（per-stock 并发守护）
- `server/services/quote_sync/repository.py`（minute_bars 批量 upsert + quote_sync_config 读写）
- `server/tables/quote_sync_config.py` / `minute_bars.py`（表访问类）
- `client/src/views/HistoryQuoteCompletion.vue`（前端页面，见《前端/页面/数据补全页面》）
- `scripts/fetch_minute_bars.py`（CLI backdoor 拉取）/ `scripts/fix_minute_bars_avg_price.py`（均价单位修正）

## 功能概述

历史分钟行情补全：管理「要跟踪并自动补全的证券」配置（`quote_sync_config` 表），从 broker his_hq 拉 1m K 线落地 `minute_bars`。

- **驱动模型**：前端按日调用 + 后端启动自动增量补全（两条路径共用同一 `sync_one_day` 核心）
- **按日同步**：`POST /api/quote-sync/sync {stock_code, date}` → 拉当日 1m → upsert `minute_bars` → 写操作记录（成功/失败 + 游标）
- **游标语义**：`last_loaded_date` = `minute_bars` 该证券实际最大 stime 日期（每次成功后重算），续补从它 +1
- **昨天封顶**：补全末天 ≤ 昨天（今天 1m 数据不全不进）
- **均价**：VWAP = `amount/(volume*100)` 元/股（A股 volume 单位是手）

## 核心实现

### 1. 按日同步端点（api/quote_sync.py）

```
POST /api/quote-sync/sync  {stock_code, date}   (require_admin)
  → manager.sync_one_day_guarded(stock, date)   # per-stock 锁
    → sync_one_day:
        fetch_one_day(stock, date)  (broker, await)
        to_record → upsert_minute_bars (to_thread)
        成功 → record_success: 重算 last_loaded + status=success + 清 error_msg
        失败 → record_failure: status=failed + error_msg (游标不动) → re-raise
  返回 {code:0, bars, last_loaded_date} / {code:1, msg:原因}
```

**关键**：`/sync` 失败体 `{code:1, msg}` 不含 `list`/`data` 字段 → 不走前端 http 拦截器全局 toast → 由页面读 `code` 处理（成功推进 / 失败停止）。

### 2. broker 客户端（broker.py）— server 自包含

- 协议同 `strategy_exec.market_data.hq_history`，但 **fields 参数化**（`open,high,low,close,volume,amount`；strategy_exec 写死 close）+ 配置读 `server.config.HIS_HQ_*`（与 strategy_exec/.env 解耦）
- 应答队列 `durable=True`（broker 端 redeclare durable，exclusive 会 406 跳过该天）
- **结束标记（change B，2026-08-30）**：broker `iquant/quota_his.py` 每天循环结束后 put 一条 `#END_OF_HIS_HQ#`，客户端收到即 break → **无数据日（周末/假日）秒回**（实测 ~0.9s，不再等 30s idle 超时）。旧 broker 无此标记时客户端**回退**到 `HIS_HQ_TIMEOUT` idle 超时（兼容）。标记常量 `END_OF_HIS_HQ_MARKER` 与 broker 端保持一致
- **空日判定**：收到结束标记或 idle 超时 → 返已收 rows。交易日 → 240 根；假日/无数据 → 0 根 = 成功空（游标照常推进，不报错）。真正可区分的 broker 故障是连接级失败（自然上抛 → `BrokerError`）
- VWAP：`avg_price = amount/(volume*100)`，`volume=0 → 0.0`
- **字段兜底（2026-09-03 改）**：broker 端 `xtquant.ContextInfo.get_market_data_ex` 实盘只返 close（2026-08-30 实测确认），其他字段返 0 占位。`to_record` 兜底策略：
  - `open/high/low = 0` → 用 `close` 兜底（单 1m bar 内 H=L=O=C，没意义区分）
  - 用 `if raw == 0` 而非 `raw or close`，避免 close=0 的极端行情被误判
  - 跟 strategy_exec.market_data.aggregator 单 1m bar 兜底语义一致

### 2b. 周末/假日走 broker（sync.py）— 方案 B（2026-09-03 改）

`sync_one_day` 顶部**不再按 `_is_weekend` 提前跳过**——所有日期（含周末、法定节假日）一律走 broker his_hq 拉取。原因：
- broker change B `END_OF_HIS_HQ_MARKER` 已在 broker 端 `iquant/quota_his.py` 每天循环结束后 put 一条 → 客户端收不到任何数据时秒级返回 `[]`（实测 ~0.9s）
- 旧 broker 无此标记时客户端回退到 `HIS_HQ_TIMEOUT` idle 超时（兼容）
- 走 broker 的好处：**`last_loaded_date` 跟实际有数据的日期一致**（即使中间隔了周末/假日），下游用户能准确知道"该证券数据补到哪天"
- 副作用：周末/假日会比"本地跳过"多一次 broker 往返（~0.9s~30s），但换取游标语义准确性更重要

`_is_weekend` 函数已删除（dead code）。

### 3. 游标重算（repository.py）

```
record_success(stock): last_loaded_date = recalc_last_loaded(stock)  # = MAX(LEFT(stime,8)) FROM minute_bars
                       status=success, error_msg='', updated_at=now
record_failure(stock, msg): status=failed, error_msg=msg[:255], updated_at=now  # 游标不动
```

游标以 `minute_bars` 实际最大日期为准（假日没数据就不推进，而非盲目 day+1）。

### 4. 配置游标初始化（add_config）

新增配置时 `last_loaded_date`：
- 已有 minute_bars 数据 → `MIN(MAX(该标 stime 日期), 昨天)`（续补从它 +1）
- 无数据 → `start_date` 前一天（使 next = `start_date` 当天，**不漏首日**）

### 5. 启动自动增量补全（main.py on_startup + manager.py）

`on_startup_quote_backfill`（skip `PYTEST_CURRENT_TEST`）→ `manager.start_startup_backfill()`：
- 读 `read_auto_pending`（auto_sync=1 且 last_loaded<昨天）
- 每只持 per-stock 锁，从 `last_loaded+1` 逐日补到 `_cap_day(end)`（= min(end 或 昨天, 昨天)）
- 某日失败 → 跳过该证券本次（游标停在失败日前，下次启动续），不影响其它证券
- 后台 `asyncio.create_task`，不阻塞启动；`on_shutdown` 取消未完成

### 6. per-stock 并发守护（manager.py）

`QuoteSyncManager` 每只证券一个 `asyncio.Lock`：启动自动补全 与 前端手动 `/sync` 共用 `sync_one_day`，同一证券串行（不重复拉同一天压 broker），不同证券互不阻塞。
