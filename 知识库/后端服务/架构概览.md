# 架构概览

## 对应代码路径

- `server/main.py`（app 入口）
- `server/infra/`（db / mq 基础设施）
- `server/api/`、`server/services/`、`server/tables/`、`server/rpc/`、`server/ws/`、`server/middleware/`、`server/utils/`

## 功能概述

EvTrade 后端是 FastAPI 单进程服务（v128.4 起单进程），通过 msgpacket/RabbitMQ 与 QMT 柜台通信，MySQL 持久化，WebSocket 向 Vue3 前端推送行情与交易事件。phase-2 拆分后按"入口 → 中间件 → 路由 → 服务 → 数据层"分层，v80+ 引入 `server/tables/` 通用表基类（TableBase），v81 迁移后所有 API 禁止直接 ORM。

## 核心实现

### 目录分层（phase-2 拆分后）

```
server/
├── main.py            入口（不写业务逻辑）
├── api/               路由层：参数校验 → 调 services/tables → 返回
├── services/          业务编排（push/、strategy/、sysconfig/、sync/、t0/）
├── tables/            数据层（TableBase，v81 后 API 唯一 DB 入口）
├── rpc/               柜台通信（facade client.py → transport/parsers/handlers）
├── ws/                WebSocket 推送
├── infra/             db / mq 基础设施
├── auth/  cache/  repo/  crawler/  enums/  middleware/  utils/  lifecycle/
```

拆分原则：client.py、db.py、constants.py 均为兼容 facade，实际实现在子模块，保持旧 import 路径不破坏。

### 请求流转

```
HTTP: 前端 → CORS → RequestLoggingMiddleware([front->svc])
      → FastAPI 路由(api/*) → services/* → tables/*(SQL) → MySQL
      → 响应 [front<-svc] → 前端

RPC:  api/* → rpc/handlers.py(ord_stk/qry_*) → RPClient.call
      → [svc->rpc] → RabbitMQ(EvTrade.Test.Req) → QMT 柜台
      → EvTrade.Test.Reply(reply listener 按 msgid 匹配 future) → [svc<-rpc]
      → 柜台主动推送 EvTrade.Test.Push → PushDispatcher → 落库 + WS 广播

WS:   柜台 push / 行情 tick → ws_manager.broadcast / broadcast_to_stock
      → [front<-svc] → 前端 /ws/{channel} 订阅者
      （行情 quote_update 数据源是 hq/hqserver.py :8765，前端可直连，不经过本 server 转发）
```

### 日志体系（server-interaction-logging）

- 统一入口：`server/utils/logflow.py` 的 `log_interaction(direction, summary, data=, elapsed_ms=, level=, trace_id=)`，logger 名 `server.interaction`。
- 4 个方向标记：
  - `[front->svc]` 前端 HTTP 请求进入
  - `[front<-svc]` HTTP 响应 / WS 广播返回前端
  - `[svc->rpc]` server 调柜台（发送 RPC 请求）
  - `[svc<-rpc]` server 收柜台消息（reply / push）
- 行格式：`[ts][level][direction][trace=XXXXXXXX] summary (elapsed ms)`，data 每个 key 缩进 2 字符一行，超 4KB（HTTP）/2KB（RPC）按字节截断。
- trace_id：8 字符 hex（`X-Trace-Id` header 优先），RPC 侧用 msgid 配对。
- 文件落地：`server/utils/file_logging.py` 的 `setup_file_logging()`，TimedRotatingFileHandler 写 `server/logs/server-YYYYMMDD.log`，midnight 切分，backupCount=6（含当天共 7 天），格式 `[asctime][levelname][name] message`。
- main.py 中 root logger 显式 basicConfig(INFO, format="%(message)s")，并禁用 `uvicorn.access`（避免与 [front<-svc] 重复）。

## 依赖关系
- 上游：Vue3 前端（HTTP + /ws）、hq/hqserver.py（行情 WS :8765）、strategy_exec 服务（signal exchange、:8001 API）
- 下游：MySQL（EVTRADE_DB_URL）、RabbitMQ（EVTRADE_RABBITMQ_URL）、QMT 柜台（msgpacket 协议）

## 修改指南
- 新增业务接口：在 `server/api/` 加路由 → 调 `server/tables/` 表类（严禁直接 ORM）→ 需要推送时用 `ws_manager`。
- 新增表：改 `server/schema.yml` → `python scripts/sync_schema.py apply`（自动生成 ORM → Alembic → tables 代码）。
- 改日志格式/保留期：`server/utils/logflow.py`、`server/utils/file_logging.py`（BACKUP_DAYS）。
- 入口 main.py 只做注册与生命周期，业务逻辑落到 services/，勿在 main.py 堆代码。
