# 信号消费者

## 对应代码路径

- `server/services/strategy/signal_consumer.py` — 唯一源文件（~293 行）

## 功能概述

`SignalConsumer` 订阅 RabbitMQ `strategy.exchange`（TOPIC）的 `EvTrade.StrategySignal` 队列，接收 strategy_exec 服务发布的 BUY/SELL/INFO 信号：实时转发前端 WS（task_progress_update 频道），live 模式的 BUY/SELL 信号则自调用 `POST /api/orders/place` 落真实委托单。aio_pika 手动 ACK + trace_id 幂等去重（24h TTL），保证 at-least-once 不丢不重下单。

## 核心实现

### 连接拓扑（start）

```
aio_pika.connect_robust(settings.RABBITMQ_URL)
channel.set_qos(prefetch_count=10)          # 限堆积
declare_queue(settings.STRATEGY_SIGNAL_QUEUE, durable=True)
bind(exchange=STRATEGY_EXCHANGE_NAME, TOPIC, routing_key="*")   # 所有 stock_code
queue.consume(_handle_message)              # 手动 ACK
```

鉴权：自调用下单用 service token（`EVTRADE_SERVICE_TOKEN`，由 /grant v92 生成的永久 JWT；缺失时回退 `EVTRADE_ADMIN_TOKEN`），httpx base_url=`http://127.0.0.1:{API_PORT}`，timeout 10s。

### _handle_message 处理链

```
1. JSON 解析失败 → ack 丢弃
2. trace_id 幂等: _is_processed → ack 跳过（防 consumer 重启重下发）
3. _broadcast_task_progress → WS task_progress_update（回测/实盘都推; 失败非致命）
4. 分流:
   - mode='backtest' → 只记录不下单, ack          （回测信号绝不落真单）
   - signal_type='INFO' → 只记录, ack
   - mode='live' 且缺 parent_task_id → 业务错 INVALID_PARENT_TASK, ack 不重试
5. v126 母单归因:
   parent_task_id 存在 → task_id=parent_task_id, user_def=strategy_name, strategy_type=2
   否则(旧路径)      → task_id=None, user_def='', strategy_type=1
6. 信号 → 下单参数:
   BUY → order_type="23"; SELL → order_type="24"
   price_type: payload 'market' → 44; 默认 limit → 11
   remark = f"strategy-{task_id}-{trace_id[:8]}"
7. POST /api/orders/place
   ├─ 2xx → _mark_processed + ack
   ├─ 400/422 业务错 → _mark_processed + ack（不重试, 防无效消息空转）
   └─ 5xx 服务错   → nack(requeue=True) 重试
8. 其他异常 → nack(requeue=True)
```

### 去重窗口

- `_processed_trace_ids: Set[str]` 内存集合；满 24h 整体清空（简化实现，新周期新窗口）。
- `_maybe_prune` 每 1h 检查一次到期。

### 前端推送（_broadcast_task_progress）

`ws_manager.broadcast("task_progress_update", {...})`，data 含 signal 完整字段（signal_type/stock_code/price/volume/msg/stime/indicators/ts/trace_id/mode）。前端链路：`ws_dispatch._onTaskProgress → wsStore.lastTaskProgress → ScriptTask.vue` 实时插信号流。广播异常被吞掉（记 warning），绝不影响 MQ ack。

## 依赖关系

```
strategy_exec (8001) ──publish──→ RabbitMQ strategy.exchange
                                       │
                              SignalConsumer（本模块）
                     ├─→ ws_manager.broadcast（task_progress_update）
                     └─→ httpx self-call POST /api/orders/place（Bearer service token）
                                └─→ 下单与撤单.md 两阶段下单
配置: RABBITMQ_URL / STRATEGY_EXCHANGE_NAME / STRATEGY_SIGNAL_QUEUE / API_PORT
环境变量: EVTRADE_SERVICE_TOKEN（回退 EVTRADE_ADMIN_TOKEN）
生命周期: server/main.py lifespan startup→start / shutdown→stop
```

## 修改指南

- **新信号类型**（如 WARN）：payload.signal_type 白名单逻辑在分流处；非 BUY/SELL 一律不触发下单。
- **下单参数映射**：order_type/price_type 映射是柜台契约（23/24、11/44），与 place.py 的 PlaceOrderRequest 保持一致。
- **错误处理红线**：业务错（4xx）必须 ack 丢弃，只有服务错（5xx/网络）才 requeue；否则一条非法信号会无限重试阻塞队列（prefetch=10 会被占满）。
- **幂等**：任何新处理分支在 ack 前必须 `_mark_processed(trace_id)`，防止重试路径重复下单。
- **测试**：可 monkeypatch `_http_client` 与 `ws_manager.broadcast`；去重窗口逻辑用注入 `_last_prune` 时间来测。
