# 脚本策略模块

## 对应代码路径

- `server/api/script_strategy/scripts.py` — 脚本 CRUD 端点（9 个）
- `server/api/script_strategy/strategies.py` — 策略 CRUD + 回测批次端点
- `server/api/script_strategy/tasks.py` — 任务端点（7 个）
- `server/api/script_strategy/strategy_orders.py` — 策略下单母单端点（7 个）
- `server/api/script_strategy/forward.py` — strategy_exec HTTP 转发
- `server/api/script_strategy/schemas.py` — Pydantic 模型
- `server/services/script_strategy/scripts.py` — 脚本服务层
- `server/services/script_strategy/tasks.py` — 任务服务层
- `server/services/script_strategy/_convert.py` — Row↔dict 转换
- `server/services/script_strategy/strategies.py` / `batches.py` / `strategy_orders.py` / `strategy_order_lifecycle.py` 等

## 功能概述

四层模型：**Script（用户 Python 脚本）→ Strategy（脚本×标的绑定）→ Task（回测任务，批次组织）→ StrategyOrder（实盘母单）**。执行不在本进程：回测/实盘运行统一转发到独立服务 strategy_exec（端口 8001，X-Internal-Token 鉴权），本模块只做 CRUD + 任务行管理 + 转发。策略模块纯回测 + 母单实盘。

## 核心实现

### Script（services/script_strategy/scripts.py）

- 复合主键 `(user_id, id)`，`id` 是字符串（用户自命名）；`is_public` 控制共享可见性（前端 ScriptDev 编辑器表单提供公开/私有开关，保存生效；他人公开脚本只读）。
- `delete_script` 级联删：script → strategy → task（防止悬挂引用）。
- `auto_create_script(user_id, code, params_schema)` — 自动命名创建：先试 `new_strategy`，已存在则递增 `new_strategy01`、`new_strategy02`…，找到不重名的后调 `create_script` 落库。前端"新建脚本"按钮直接调此接口，点击即创建并在列表显示，不等保存。

### Strategy（api/strategies.py）

- 字段：`strategy_id, user_id, script_id, name, status(draft/active/archived), is_public, stock_code(绑定标的), best_params(JSON)`。
- 权限矩阵：owner/admin 全量；他人公开策略 → 精简卡片（回测 403 BACKTEST_FORBIDDEN）；他人私有/不存在 → 404 NO_STRATEGY。
- 无 best_params 不可建/启动母单（400 NO_BEST_PARAMS）。

### 回测批次（strategies.py + batches.py）

```
POST /strategies/{id}/backtest  (202 Accepted)
1. svc.create_backtest_batch: 生成 batch_no + N 行 StrategyTask
   - mode=single: req.params 1 组
   - mode=sweep: param_ranges 展开（int/float 含端点 / choice 值列表 / string 固定）
2. 转发: sweep → _forward_run_sweep(payload含task_ids)
        single → _forward_run_task(task_id, payload)
3. 返回 {batch_no, total_runs, mode, metric, over_soft_limit}
```

- 任务状态机：`queued → running → finished / failed / stopped / abandoned`。
- 重测：原批次 task 全部废弃，新 batch_no 重建转发；运行中批次 409 BATCH_RUNNING。
- 列表轻量化：`TASK_LIST_COLUMNS` 白名单排除 backtest_result/positions/live_signals 等 BLOB 列（防 MySQL 1038 Out of sort memory → 500）；详情 query_one 才返回全列。

### 任务服务层（services/script_strategy/tasks.py）

- `list_tasks(user_id, is_admin, status, mode, strategy_id, limit≤200)`。
- `get_task_signals`：backtest 模式从 `backtest_result.best.signal_log` 取信号流 + `best.progress_log`（**2026-08-30 起新任务为空** — 全量逐 bar 不再落库，前端进度 Tab 已删；存量老行旧 blob 仍可能含，前端 `|| []` 兜底）；`get_task_audit` 从 strategy_script_audit 表读永久审计（支持 trigger_type/trd_date 过滤）。
- `_convert.py`：`task_row_to_dict`（26 字段）、`_row_metric_value`（列优先，老行回退解析 backtest_result blob；回退链 sharpe → total_return → pnl/initial_cash）。

### 母单实盘（strategy_orders.py）

```
POST /strategy-orders {strategy_id} → 建母单
POST .../start (202): svc.start_strategy_order
   → 建 live task + build_start_forward_payload(parent_task_id=母单active_task_id)
   → _forward_run_task 转发 strategy_exec
POST .../stop: 改母单 status + 转发 /internal/stop-task（转发失败不阻断, 母单状态已更新）
POST .../close: 终态关闭
GET  .../children: 母单子单（orders.strategy_type=2 且 task_id=母单任务）
```

错误码映射：STRATEGY_ORDER_NOT_FOUND/NO_STRATEGY→404，FORBIDDEN→403，NO_BEST_PARAMS→400，STRATEGY_ORDER_INVALID_STATE→409。

### forward.py 转发约定

- httpx.AsyncClient，header `X-Internal-Token: settings.STRATEGY_EXEC_API_TOKEN`，base `settings.STRATEGY_EXEC_API_URL`（默认 8001），timeout 60s。
- 经 strategies.py 命名空间引入（`from ... import _forward_run_task`）以兼容测试 monkeypatch。

## 依赖关系

```
api/script_strategy/* ──→ services/script_strategy/*（svc facade）
                     ──→ auth/deps.get_current_user（JWT）
services 层 ──→ tables: StrategyScript / Strategy / StrategyTask / StrategyScriptAudit / StrategyOrder
api 层 stop 转发 ──→ strategy_exec (8001) /internal/stop-task
信号闭环: strategy_exec → RabbitMQ → signal_consumer（见 信号消费者.md）
任务停止兜底: strategy_exec 不可达时本地标 stopped（api/tasks.py stop_task_endpoint fallback）
```

## 修改指南

- **新增端点**：先加 services 层函数再补 api 路由；错误统一抛 `StrategyError(code, msg)` 并在 `_HTTP_BY_CODE` 映射。
- **执行逻辑**：回测/实盘引擎在 strategy_exec 服务（另一个进程），本模块不要引入引擎代码；转发 payload 契约改动需两端同步。
- **列表性能**：任何新列表端点必须用 `columns=TASK_LIST_COLUMNS` 类白名单，勿 SELECT 大 BLOB 列。
- **级联删除**：脚本删除链 script→strategy→task 在 `delete_script`；新增关联表时要补进级联，否则悬挂行。
- **母单归因**：子单识别依赖 orders.task_id=母单 active_task_id + strategy_type=2（signal_consumer 写入），改下单归因字段需三处同步（place schema / signal_consumer / strategy_orders children 查询）。
