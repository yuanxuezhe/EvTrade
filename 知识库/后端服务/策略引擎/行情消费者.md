# 行情消费者

## 对应代码路径

- `server/services/strategy/quote_consumer.py` — 唯一源文件（~344 行）

## 功能概述

`QuoteConsumer` 是后端 WebSocket 客户端，连接 hqserver（默认 `ws://127.0.0.1:8765`，`settings.HQ_WS_URL`）接收实时 tick：解析 31 字段行情 → 写内存 `quote_cache`（O(1)，持久化由 flusher 负责）→ tick 先入 batch buffer，满 50 条或 1 秒（双阈值）才一次 `broadcast_batch` 推给订阅了相应股票的前端 WS 连接（/ws/quote_update），1 个 ws frame 装 N 条 tick。纯行情管道（无策略引擎耦合），不做股票级去重（同窗口内同股票多 tick 全部保留）。

## 核心实现

### 生命周期与容错

```
start() → _main_loop（永久直到 stop）
  ├─ _connect(): 指数退避重连 1s → 2s → 4s → ... → 30s 上限
  │           connect(url, ping_interval=15, ping_timeout=60)  # 主动 ping + 行情低谷容错
  ├─ asyncio.gather(_consume_loop, _health_loop)  # 断连时 gather 自动取消
  └─ 异常 → 固定 sleep 1s 后重连（指数退避在 _connect 内部）

_health_loop: 每 30s 心跳 log（ticks_total / last_tick_age）
              60s 无 tick → warn（连接活着只是行情低谷, 不触发重连）
```

### _parse_tick（hqserver 消息契约）

hqserver payload：`{"type":"quote","channel":"quote_update","data":{"stock_code","last_price","fields":[31字段],"body":"..."}}`

31 字段索引（QMT publisher format_quote 透传）：

```
[0] stock_code        [1] datetime(yyyyMMddHHmmss.sss)  [2] last_price
[3] open  [4] high  [5] low  [6] prev_close
[7] volume  [8] amount
[9] openInt  [10] transactionNum
[11..15] ask1..ask5_price   [16..20] bid1..bid5_price
[21..25] ask1..ask5_vol     [26..30] bid1..bid5_vol
```

解析产出：

| 输出 | 内容 | 去向 |
|---|---|---|
| `snapshot` | 23 字段 dict（缺字段补 0；`f()` float / `iv()` 整数） | quote_cache.set() |
| `fields` | 原 31 字段数组 | 前端 quote store |
| `body` | 原 GBK 字符串 | 前端 quote store |

非 quote_update 消息 / 坏 JSON → 返 None 静默忽略。

### _fanout_tick 与批量 flush（quote-batch-flush）

```
_fanout_tick（每根 tick）:
1. self._latest_price[stock_code] = last_price   # 内存最新价表
2. quote_cache.set(snapshot)                      # O(1) 写 + dirty 标记（不直接 MySQL, 旧路实测 200ms/次锁死 6 ticks/s）
3. tick 入 _batch_buf（asyncio.Lock 内 append; 不去重, 同股票多 tick 全保留）
   buffer ≥ QUOTE_BATCH_MAX（默认 50）→ 立即 _flush_batch

_flush_batch: 取出 buffer 全部 tick → ws_manager.broadcast_batch(ticks)
   # 按订阅过滤, 每个 ws 客户端只收自己订阅的股票; 1 frame 装 N 条 tick; 失败仅记 log 非致命

_flusher_loop（start 时 ensure_future 的后台 task）:
   每 max(50, QUOTE_BATCH_FLUSH_MS//4)ms（默认 100ms）检查一次,
   距上次 flush ≥ QUOTE_BATCH_FLUSH_MS（默认 1000ms）→ _flush_batch（慢市兜底）
stop(): cancel flusher task + final flush（最后一批不丢）+ 关 ws
```

## 依赖关系

```
hqserver (ws://127.0.0.1:8765) ──→ QuoteConsumer
                     ├─→ cache/quote_cache.py get_quote_cache().set()（见 行情缓存.md）
                     └─→ ws/manager.py broadcast_batch（/ws/quote_update 前端频道, 按订阅过滤）
持久化: cache/quote_cache_flusher.py 后台批量 UPSERT（本模块不碰 DB）
配置: settings.HQ_WS_URL / QUOTE_BATCH_MAX(50) / QUOTE_BATCH_FLUSH_MS(1000)
启动: server/main.py startup → get_quote_consumer()（asyncio.ensure_future 后台 task）
```

## 修改指南

- **消息契约**：fields 31 索引是 QMT publisher 与 hqserver 的透传契约，上游加字段只能向后追加（尾部 append），不能插位。
- **不要在 fan-out 路径加 DB 写**：tick 峰值 ~4000+/s，任何同步 IO 都会积压；持久化一律走 quote_cache dirty + flusher。
- **快照字段**：snapshot 23 字段与 quote_snapshots 表列、`repo/quote_snapshots.to_dict` 三方对齐，加字段需同步三处。
- **重连语义**：recv 异常 raise 给 _main_loop 走重连是有意设计；不要在 _consume_loop 内部 try-swallow，否则死连接不自愈。
- **单例**：模块级 `_quote_consumer` 单例，测试用 `close_quote_consumer()` 复位。
