# 对账

## 对应代码路径

| 文件 | 说明 |
|---|---|
| `server/api/admin/reconcile.py` | 对账配置 CRUD + 报告查询（148 行） |

## 功能概述

对账模块负责「本地数据 vs 柜台（QMT via RPC）数据」的一致性：

- **API 层**（admin/reconcile.py）：
  - `GET/PATCH /api/admin/reconcile/config` — 读写对账配置（存 sysconfig，user='0'）
  - `GET /api/admin/reconcile/reports` — 近 90 天报告列表（LIMIT 200）
  - `GET /api/admin/reconcile/reports/{trd_date}/{mode}/{created_at}` — 单报告详情（复合主键）
- **服务层**（services/reconcile.py）：
  - `do_reconcile(db, new_trd_date, by_user, reconcile_kind)` — 拉柜台 qry_positions → 计算 diff → 写 `reconcile_report` → 按 auto_reconcile 覆盖本地 → 切日（UPDATE sys_status id=1）
  - `_apply_broker_data` — init 模式全表覆盖 Position
  - `_update_last_asset` — 计算期初总资产 last_asset = cash + Σ(last_vol × prev_close)

两种 reconcile_kind：
- `'init'`（系统初始化）：qry_positions RPC 一次性同步 → **全表覆盖** positions
- `'incremental'`（兜底/manual）：**不动 positions**（pos_push 接管），仅记录报告 + 切日

委托/成交不参与对账，靠 push（ord_cfm / trd_cfm）增量 upsert。

### reconcile_report 表结构（复合主键）

| 列 | 类型 | 说明 |
|---|---|---|
| trd_date + mode + created_at | 复合 PK | 报告唯一标识（report_id 即 created_at 的 int 时间戳） |
| diffs_json | TEXT | 摘要（**只记计数**，防 64KB 超限 DataError 1406） |
| broker_positions_json / local_positions_json | TEXT | 柜台/本地持仓快照全量 |
| broker_asset_json / local_asset_json | TEXT | 柜台/本地资产快照 |
| rpc_status | str | ok / partial / failed |
| error_message | str(512) | RPC 错误拼接 |
| created_by | int | 触发用户 id |

## 核心实现

### 1. do_reconcile 主流程

```python
async def do_reconcile(db, new_trd_date, by_user, reconcile_kind="incremental") -> Dict:
    cfg = get_reconcile_config(db)   # {auto_reconcile: 0/1, auto_use_broker_data: 0/1}

    # 1) 拉柜台持仓（资金不同步，由 rpc_health 5s 定时同步）
    try:
        positions_data = _safe_dict_list(await qry_positions())   # code!=0 → []
    except Exception as e:
        rpc_errors.append(f"qry_positions: {e}"); positions_data = []
    assets_data = []
    rpc_status = "ok" if not rpc_errors else ("failed" if not positions_data else "partial")

    # 2) 读本地快照（对比用）
    local_positions = [{"stock_code": p.stock_code, "vol": p.vol,
                        "avl_vol": p.avl_vol, "cost_price": p.cost_price}
                       for p in Positions.query_all()]

    # 3) 写报告（diffs_json 只记摘要计数，防 TEXT 超 64KB）
    report = ReconcileReport.add_one({
        'trd_date': new_trd_date,
        'mode': "auto" if cfg["auto_reconcile"] else "manual",
        'created_at': now,
        'diffs_json': json.dumps({'rpc_errors': rpc_errors,
                                  'broker_positions_count': len(positions_data),
                                  'local_positions_count': len(local_positions), 'assets_count': 0}),
        'broker_positions_json': json.dumps(positions_data, default=str),  # ... 其余快照列
        'rpc_status': rpc_status,
        'error_message': "; ".join(rpc_errors)[:512],
        'created_by': int(by_user) if by_user else None,
    })

    # 4) 全部 RPC 失败 → 报告已写，返失败（不切日）
    if rpc_status == "failed":
        return {'ok': False, 'report_id': int(now.timestamp()), 'error': f"全部 RPC 失败: ..."}

    # 5) auto_reconcile=True → 覆盖本地（仅 init 模式覆盖 positions）
    applied = False
    if cfg["auto_reconcile"]:
        if reconcile_kind == 'init':
            applied = _apply_broker_data(db, new_trd_date, positions_data, assets_data)
        else:
            applied = True   # incremental: 不动数据，仅标记成功让切日能跑

    # 6) 切日（applied 或 auto_reconcile=False 均切）
    if applied or not cfg["auto_reconcile"]:
        SysStatus.upsert_one({'id': 1, 'trd_date': new_trd_date, 'status': 'active',
                              'initialized_at': now, 'initialized_by': int(by_user), ...})
    return {'ok': True, 'report_id': int(now.timestamp()), 'applied': applied, ...}
```

### 2. _apply_broker_data（init 全表覆盖）

```python
def _apply_broker_data(db, trd_date, positions_data, assets_data) -> bool:
    db.query(Position).delete()                      # 清空本地持仓
    for p in positions_data:                         # 逐行插入柜台数据
        db.add(Position(
            stock_code=p['stock_code'], stock_name=p.get('stock_name', ''),
            last_vol=int(p.get('last_vol', 0) or 0), avl_vol=..., vol=...,
            cost_price=_round_scale(p.get('cost_price', 0), get_stock_scale(db, stock_code)),
            synced_at=utcnow_naive(), synced_from='rpc_reconcile'))
    # assets: 初始化不同步资金（assets_data 为空跳过，不删已有行）
    if assets_data: ...
    _update_last_asset(db)                           # 期初总资产
    db.commit()
    return True
```

注意：parser 输出 dict 键名已与 Position ORM 列名对齐（volume/avl_amt/avg_price 在 `_parse_positions` 边界完成重命名）。`cost_price` 按 `stocks.scale` 保留精度。

### 3. _update_last_asset（期初总资产）

```python
def _update_last_asset(db) -> None:
    asset_row = db.query(Asset).filter(Asset.id == 1).first()   # 同一事务内可见未 commit 的持仓
    cash_now = float(asset_row.cash or 0)
    prev_close_sum = 0.0
    for p in db.query(Position).all():
        if p.last_vol <= 0: continue
        qs = db.query(QuoteSnapshots).filter_by(stock_code=p.stock_code).first()
        prev_close_sum += p.last_vol * float(qs.prev_close or 0 if qs else 0)
    asset_row.last_asset = cash_now + prev_close_sum
```

- `last_asset` 当天不变，前端当日盈亏 = total_asset(now) − last_asset
- `quote_snapshots.prev_close` 由 broker qry_snapshots/qry_ast 同步写入
- 异常仅 log，last_asset 留 default 0（非致命）

### 5. 对账配置

配置不再有独立表，走 sysconfig（user='0'）：
- `auto_reconcile`（0=人工/1=自动）
- `auto_use_broker_data`（0=本地/1=柜台）

PATCH 时 `sysconfig.set_value("0", key, "1"/"0", desc, admin_user.username)` 同步更新 cache+DB。

响应类型细节：`auto_reconcile: bool`（前端 el-switch 用），`auto_use_broker_data: int`（el-radio 用，**不要转 bool**，否则 `:value="1"` 匹配不上）。

## 依赖关系

## 修改指南

- **新增对账维度**（如委托对比）：在 `do_reconcile` 第 1 步追加 RPC 调用，失败计入 `rpc_errors`；快照 JSON 列需同步加表列（DDL + alembic/自研 migration）
- **调整报告保留期**：改 `admin/reconcile.py` 的 `REPORT_RETENTION_DAYS = 90` 与 SQL 中 `LIMIT 200`
- **init 也想覆盖资金**：在 `do_reconcile` 恢复 `qry_asset` 调用并填充 `assets_data`（当前刻意去掉，因 rpc_health 5s 同步已接管；恢复前确认不会把 last_asset 冲 0，见 rpc_health 的 last_asset 陷阱说明）
- **增量模式改为也覆盖 positions**：改 `do_reconcile` 第 5 步 `else` 分支——但会破坏 pos_push 累计态，不建议
- **diffs_json 超限**：全量 positions 塞 diffs_json 会触发 MySQL DataError 1406（TEXT 64KB 上限），全量数据必须走专用列 `broker_positions_json` 等
- **created_at 解析失败**：`get_report` 的 4 种格式 strptime 兜底已覆盖常见情况，新格式加到 fmt 元组即可
