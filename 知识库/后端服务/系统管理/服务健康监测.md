# 服务健康监测

## 对应代码路径

| 文件 | 说明 |
|---|---|
| `server/services/rpc_health.py` | RPC 三态健康监测 + 资金 5s 定时同步（337 行） |
| `server/api/deps.py` | `require_rpc_ok` 路由依赖（引用本模块 check_ok） |
| `server/ws/manager.py` | `system_update` 通道广播 |

## 功能概述

rpc_health 维护与 QMT 柜台（RabbitMQ RPC）的通信健康状态，并承担资金定时同步：

- **三态状态**（全局模块级变量 `_rpc_status`）：
  - `0 = RPC_STATUS_OK` 正常（可下单/可日初）
  - `1 = RPC_STATUS_COMM_ERROR` 通信异常（下单直接拒绝）
  - `2 = RPC_STATUS_DATA_ERROR` 数据异常（通信通但无有效数据）
- **后台探测循环**：每 5 秒一轮（收到应答后间隔），单次 RPC 超时 15 秒；**连续 3 次失败才切换异常**（防抖），**一次成功立即恢复 OK**
- **资金同步**：探测成功时 `qry_asset` 结果 upsert 进 `assets` 表（id=1），并 WS 推 `asset_update`
- **WS 推送**：状态变更推 `system_update` 通道 `type='rpc_status'`；正常时每轮推 `type='asset_update'`；前端 AppHeader.vue 右上角图标据此显示绿/红/黄

使用方：place.py（下单前 check_ok）、sys_status.py（日初前，经 require_rpc_ok）、main.py（启停 task）、asset.py（GET /api/asset 拿状态详情）。

## 核心实现

### 1. 状态读写

```python
_rpc_status: int = RPC_STATUS_OK      # 模块级全局
_last_ok_at: float = 0.0
_last_err_msg / _last_status_msg / _last_queue_depth

def check_ok() -> bool:
    return _rpc_status == RPC_STATUS_OK

def get_status() -> dict:             # /api/asset、诊断、前端首屏用
    return {"ok": check_ok(), "status": _rpc_status,
            "message": _STATUS_TEXT.get(_rpc_status, ""),
            "last_status_msg": _last_status_msg, "last_ok_at": _last_ok_at,
            "last_err_msg": _last_err_msg, "request_queue_depth": _last_queue_depth}
```

### 2. 单轮探测 _probe_once（积压 → 超时 → 应答解析）

```python
async def _probe_once() -> tuple:     # 返回 (success, detail)
    # 1) 在途积压检查 → 失败则不发 qry_asset（防雪崩）
    depth = await _get_request_queue_depth()
    pending_count = await _get_pending_count()          # len(rpc.pending)
    if pending_count > 0 or depth >= MAX_PENDING:
        return (False, f"RPC pending 积压 ({pending_count} in-flight)")

    # 2) RPC 调用，15s 超时
    try:
        data = await asyncio.wait_for(qry_asset(), timeout=TIMEOUT_SEC)
    except (asyncio.TimeoutError, Exception) as e:
        return (False, str(e))

    # 3) 应答解析：code==0 且有数据 → 成功
    code = int(data.get("code", -1)); row_count = len(data.get("list", []))
    if code == 0 and row_count > 0:
        a = data["list"][0]
        # 关键：读现有 last_asset 携带进 upsert，防冲回 0
        existing = await asyncio.wait_for(asyncio.to_thread(Assets.query_one, id=1), timeout=2.0)
        last_asset = float(getattr(existing, 'last_asset', 0) or 0) if existing else 0.0
        Assets.upsert_one({
            "id": 1,
            "cash": float(a.get("cash", 0) or 0),
            "available": float(a.get("cash", 0) or 0),
            "frozen_cash": float(a.get("frozen_cash", 0) or 0),
            "market_value": float(a.get("market_value", 0) or 0),
            "total_asset": float(a.get("total_asset", 0) or 0),
            "last_asset": last_asset,       # 期初总资产（reconcile 写入，当天不变）
            "synced_at": utcnow_naive(), "synced_from": "rpc_sync",
        })
        _last_ok_at = time.time()
        return (True, "")
    # 4) 应答但 code!=0 或空数据 → 失败
    return (False, data.get("msg") or f"code={code}" or "code=0 but row_count=0")
```

**last_asset 陷阱**：`assets.last_asset` 在 MySQL 是 NOT NULL 无默认值，`upsert_one` 缺该字段会补 0 并写进 ON DUPLICATE KEY UPDATE，把 reconcile 写的期初总资产冲回 0 → 仪表盘趋势百分比 = 盈亏/1 显示天文数字。**必须先读现有值再携带进 upsert。**

### 3. 状态机 _sync_loop（防抖切换）

```python
async def _sync_loop():
    consecutive_failures = 0
    while True:
        try:
            success, detail = await _probe_once()
            if success:
                if _rpc_status != RPC_STATUS_OK:            # 一次成功立即恢复
                    _set_status(RPC_STATUS_OK)
                    await _broadcast_rpc_status()
                consecutive_failures = 0
                await _broadcast_asset()                    # 正常时推 asset_update
            else:
                consecutive_failures += 1
                if consecutive_failures >= _CONSECUTIVE_FAILURE_THRESHOLD:
                    if _rpc_status == RPC_STATUS_OK:        # 只切一次 + 只广播一次
                        _set_status(RPC_STATUS_COMM_ERROR, err_msg=detail)
                        await _broadcast_rpc_status()
                    if consecutive_failures == _CONSECUTIVE_FAILURE_THRESHOLD:
                        await asyncio.sleep(SYNC_INTERVAL_SEC)  # 刚达阈值多等一轮
        except Exception as e:
            log.warning("rpc_health loop error: %s", e)
        finally:
            await asyncio.sleep(SYNC_INTERVAL_SEC)
```

探测永不中止（进程在跑就一直探）；`_probe_once` 不直接改状态，状态变更由 `_sync_loop` 统一决策。

### 4. 全部超时保护

RabbitMQ channel 关闭/重连窗口期，各步骤都可能挂死，全部包 wait_for：

| 操作 | 超时 |
|---|---|
| `get_rpc_client()` | 5s |
| `queue.declare(passive=True)`（拿 message_count） | 5s |
| `Assets.query_one`（同步 SQL） | 2s + `asyncio.to_thread`（防阻塞 event loop） |
| `ws_manager.broadcast` | 2s（慢 WS 消费者/死连接不拖死探测循环） |

### 5. 启停（main.py lifespan 调用）

```python
async def start_sync():
    if _sync_task is not None and not _sync_task.done(): return   # 幂等
    _sync_task = asyncio.ensure_future(_sync_loop())

async def stop_sync():
    if _sync_task is not None:
        _sync_task.cancel()
        try: await _sync_task
        except (asyncio.CancelledError, Exception): pass
        _sync_task = None
```

### 6. WS 推送载荷

```python
# rpc_status（状态变更时）
{"type": "rpc_status", "data": get_status()}          # 广播到 system_update 通道
# asset_update（每轮成功时）
{"type": "asset_update", "data": {"cash", "available", "frozen_cash",
                                  "market_value", "total_asset", "synced_at"}}
```

## 修改指南

- **调整探测频率/超时**：改 `SYNC_INTERVAL_SEC` / `TIMEOUT_SEC` / `_CONSECUTIVE_FAILURE_THRESHOLD` 三个模块级常量；间隔过短会加重 broker 压力
- **启用状态 2（数据异常）**：当前 `_probe_once` 的失败统一由 `_sync_loop` 映射为 COMM_ERROR；若需区分「超时/积压→1，应答但 code!=0→2」，在 `_probe_once` 返回值中携带建议状态码并在 `_sync_loop` 分支调用 `_set_status`
- **新增同步数据**（如每轮拉持仓）：**不建议**——持仓由 pos_push 推送驱动，加轮询会与推送冲突；确需加时仿 `_probe_once` 中 assets upsert 模式（to_thread + 2s timeout + 读改写保护既有字段）
- **upsert assets 新字段**：务必检查是否需要「读现有值携带」模式（last_asset 教训），否则定时同步会把一次写入的静态字段周期性冲掉
- **广播频率**：rpc_status 只在状态翻转时广播一次；asset_update 每轮（5s）一次。若前端嫌吵，在 `_broadcast_asset` 加节流计数
- **单测**：模块级全局变量在测试间会残留，测试前需手动重置 `_rpc_status = RPC_STATUS_OK` 等
