# 行情接口与订阅

## 对应代码路径

- `server/api/quote.py` — 行情快照 REST API
- `server/repo/quote_snapshots.py` — DB 兜底读取（get_latest / get_latest_multi / to_dict / upsert_batch）
- `server/ws/manager.py` — `broadcast_to_stock` 前端订阅推送（被 quote_consumer 调用）

## 功能概述

行情读取路径：REST 快照查询走 **cache 优先 + DB 回填**（2026-07-10 quote-cache 模式），latest-only 模型（每 stock_code 1 行）。前端实时行情由 WS 订阅 `/ws/quote_update` 获得（quote_consumer 按 stock_code 精确 fan-out），REST 只服务"加载时拿初始快照"场景。

## 文件清单

| 端点（server/api/quote.py，前缀 /api/quote） | 说明 |
|---|---|
| POST /api/quote/snapshots | 批量查最新快照（body: `{stock_codes: [...]}`，上限 200） |
| GET /api/quote/snapshot/{stock_code} | 单条查 |
| GET /api/quote/snapshot/{stock_code}/depth | 单条 + 5 档买卖深度（供 QuotePanel.vue / Trade.vue） |

响应模型：`SnapshotsResponse{code, msg, snapshots: {stock_code: snapshot_dict}}`、`SnapshotResponse{code, msg, snapshot}`；查无数据返回 `code=404`（HTTP 仍 200，业务码风格）。

## 核心实现

### post_snapshots（批量）

```
1. 空 list → 空 snapshots 直接返回
2. >200 条 → HTTPException 400 "max 200 stock_codes per request"
3. 去重 + strip: {c.strip() for c in ...}
4. cached = cache.multi_get(codes)            # 内存命中
5. missing = codes - cached                   # 收集 miss
6. miss → repo_get_latest_multi(missing) 查 DB → repo_to_dict → cache.set() 回填
7. DB 也没有（从未有 tick 的新股票）→ 静默跳过
```

### get_snapshot（单条）

`cache.get(stock_code)` 命中直返；miss → `repo_get_latest` 查 DB → 回填 cache → 返回；DB 无 → `code=404, msg="no snapshot for {stock_code}"`。

### v81.4 tables-migration

原 `Depends(get_db)` 已删除；repo 函数签名保留 `db=` 占位但实际不依赖 session（quote_cache 兜底 + `QuoteSnapshots.query_*` tables 层调用）。

### 快照字段（与 quote_snapshots 表一致）

`stock_code, last_price, open_price, high_price, low_price, prev_close, volume, amount, bid1..bid5_price/vol, ask1..ask5_price/vol, ts`（5 档买卖各 10 字段）。

### 前端订阅触发点

- 持仓页加载 → `POST /api/quote/snapshots {stock_codes: holdings.codes}` 拿初始市值。
- Trade.vue 输入代码 → `GET /api/quote/snapshot/{code}/depth` 拿五档盘口。
- 之后实时更新走 WS `/ws/quote_update`（broadcast_to_stock 严格按订阅过滤，零订阅者不推）。

## 依赖关系

```
api/quote.py ──→ cache/quote_cache.py（读 + 回填）
             ──→ repo/quote_snapshots.py（DB 兜底读, tables 层）
实时链路: quote_consumer._fanout_tick → ws_manager.broadcast_to_stock（本模块不参与）
写链路: cache/quote_cache_flusher.py → repo.upsert_batch（本模块不参与）
```

## 修改指南

- **加端点**：保持"cache 优先 + miss 查 DB + 回填 cache"三段式；直接查 DB 会退回旧性能问题。
- **批量上限**：200 上限是防单请求打爆 DB 回填路径；调大需先评估 DB 回填最坏情况。
- **404 语义**：本模块用业务码（HTTP 200 + code=404）风格，与全局 HTTPException 风格不同，前端已适配，勿混改。
- **深度端点**：depth 就是完整快照（快照本身含 5 档），无独立深度查询逻辑；若未来拆分轻量快照/深度两种模型，注意与 quote_consumer snapshot 23 字段对齐。
