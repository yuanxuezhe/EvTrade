# 行情缓存

## 对应代码路径

- `server/cache/quote_cache.py` — 内存缓存 QuoteCache（~170 行）
- `server/cache/quote_cache_flusher.py` — 周期 flush 到 MySQL（~108 行）
- `server/tables/quote_snapshots.py` — quote_snapshots 表（30 字段，主键 id，latest-only 每股票 1 行）
- `server/repo/quote_snapshots.py` — `upsert_batch` 批量写入

## 功能概述

行情热路径性能层。设计动机：tick 直写 MySQL UPSERT 实测 p50=200ms，backend 处理速率锁死 ~6 ticks/s，而 hqserver 推送 ~4000+ ticks/s（99.85% 积压）。方案：tick → 内存 cache O(1) 写 → 后台 flusher 定时/阈值触发批量 UPSERT。**cache 是读的 single source of truth，DB 是持久化备份**。

## 核心实现

### QuoteCache 数据结构

```python
_snapshots: Dict[str, dict]   # 主数据 {stock_code: snapshot23字段}
_dirty: Set[str]              # 自上次 flush 后有更新的 code
_dirty_lock: threading.Lock   # 仅 dirty 路径加锁; set/get 读写路径无锁（GIL 保护原子性, 热路径最大化）
_stats: {hits, misses, sets, flushes, last_flush_ts/count/duration_ms}
```

### 三条路径

```
write（热路径无锁）: set(snapshot) → _snapshots[code] = snapshot + _dirty.add(code)
read（热路径无锁）:  get(code) / multi_get(codes) → miss 计数, 调用方走 DB 回填
flush（加锁）:       pop_dirty() 原子取出 (snapshots, codes)
                    成功 → record_flush(count, duration_ms)
                    失败 → restore_dirty(codes) 回滚标记下轮重试
```

### flusher 触发条件（任一）

| 条件 | 配置 | 默认 |
|---|---|---|
| 定时器 | `QUOTE_CACHE_FLUSH_INTERVAL` | 60s |
| 阈值 | `QUOTE_CACHE_FLUSH_DIRTY_THRESHOLD` | 100 个 dirty |

```
_flush_once:
1. pop_dirty() → 无 dirty 直接返回（零开销）
2. asyncio.to_thread(_do_upsert_all)  # 线程池执行, 不阻塞事件循环
   - db_session() 内 quote_repo.upsert_batch(db, snapshots)
   - executemany 批量 vs 单条 ~4.7x 提升
3. 部分失败（n_written < count）→ log warning, 下周期补
4. 整批失败（DB 不可用）→ restore_dirty 回滚

_periodic_flush_loop: while True 循环, CancelledError 时做 final flush 再退出（shutdown 落盘）
```

### 一致性权衡

- 进程崩溃 → 最多丢 `QUOTE_CACHE_FLUSH_INTERVAL` 秒（默认 60s）行情快照（仅最后价，非成交数据）。
- API 读 miss 时回填 cache（见 行情接口与订阅.md），启动冷窗口由 DB 兜底。

### quote_snapshots 表（tables/quote_snapshots.py）

30 字段：id(PK), stock_code, last_price, open/high/low/prev_close, volume, amount, bid1..5_price/vol, ask1..5_price/vol, ts(datetime)。latest-only：业务上每 stock_code 保留最新 1 行（由 repo 层 UPSERT 键控制）。

## 依赖关系

```
quote_consumer（写）──set()──→ QuoteCache ←──get()/multi_get()── api/quote.py（读）
                                    │ pop_dirty
                quote_cache_flusher ─┴─→ repo/quote_snapshots.upsert_batch → MySQL
启动: main.py startup → start_quote_cache_flusher()（asyncio.create_task, name="quote_cache_flusher"）
shutdown: cancel task（final flush）
```

## 修改指南

- **热路径红线**：`set`/`get`/`multi_get` 必须保持无锁纯 dict 操作；任何新逻辑（统计、校验、转换）加在这里都会拖慢 4000+/s 的 tick 流。
- **flush 失败语义**：`restore_dirty` 是唯一恢复手段，新增 flush 逻辑（如多表写入）失败时必须回滚 dirty，否则静默丢数据。
- **持久化频率**：调小 interval 提高持久性但增加 DB 压力；调大则崩溃丢数据窗口变大。行情快照可丢（最新 tick 很快覆盖），不要为此加同步落盘。
- **统计**：`stats()` 输出含 hit_rate/dirty_count，可挂到健康检查端点；新增统计字段同步此处。
- **单例与测试**：生产代码一律 `get_quote_cache()`；测试用 `reset_quote_cache_for_tests()` 复位，勿直接改模块级 `_cache`。
