# 测试体系

## 对应代码路径

- `pytest.ini`（根目录，pytest 全局配置）
- `conftest.py`（根目录，模块预加载与裸名别名）
- `tests/`（Python 测试主目录）、`tests/strategy_exec/conftest.py`
- `tests/client/vitest.config.js` + `tests/client/**/*.test.js`（前端 Vitest）
- `scripts/e2e/`（端到端脚本，需活服务）
- `server/tests/`（服务层附加测试）

## 功能概述

三层测试结构：①`tests/` 单元/集成测试（pytest，默认 testpaths）②`tests/client/` 前端测试（Vitest + happy-dom/jsdom）③`scripts/e2e/` 端到端验证（打活 backend）。pytest 模式通过 `PYTEST_CURRENT_TEST` 环境变量跳过 RPC/WS 等真实外部依赖，保证单测可离线跑。

## 核心实现

### pytest.ini 关键配置

```ini
[pytest]
asyncio_mode = auto          # async 测试函数无需 @pytest.mark.asyncio 装饰
testpaths = tests            # 裸跑 pytest 即收集 tests/
addopts = --ignore=tests/server/rpc   # test_rpc.py 连活 RabbitMQ，默认排除
```

### 根 conftest.py 的两个机制

1. **Base 重复注册修复**：测试文件常用 `sys.path.insert(0,'server/')` 后 `from db import Base`（裸名），与生产代码 `from server.db import Base`（限定名）会加载 orm.py 两次，撞 SQLAlchemy `Table already defined`。解法：conftest 预加载约 30 个 `server.*` 模块，再把同一模块对象以裸名（`db`/`models.orm`/`api.orders.place` 等）注册进 `sys.modules`，两种 import 风格命中同一实例。
2. **AsyncMock backport**：Python 3.8+ 直接用 stdlib；旧版注入自制 AsyncMock（awaitable + await_count/await_args）到 `unittest.mock`。

### PYTEST_CURRENT_TEST 跳过模式

pytest 运行时自动设置 `PYTEST_CURRENT_TEST` 环境变量，`server/main.py` 的各 startup 钩子检测到即跳过真实外部依赖（打印 `[INIT] pytest mode: skip ...`）：

| startup 钩子 | pytest 下的行为 |
|---|---|
| `on_startup_rpc` | 跳过 RPC 客户端（否则连真 RabbitMQ 会 SSL hang） |
| quote consumer 启动 | 跳过（避免 WS 连真行情污染测试） |
| quote cache flusher | 跳过 MySQL 周期回写 task |
| auth session sweep | 跳过 token 过期清理协程 |

配套 fixture 约定（历史 change `2026-07-08-fix-v20-pytest-backend`）：module 级 `drop_all+init_db` + 每 test 软清（白名单保留 users/sys_status 等基础表）。

### 前端测试（Vitest）

- 运行：`client/` 目录下 `npm run test`（即 `vitest run --config ../tests/client/vitest.config.js`）；`npm run test:watch` 监听
- 环境：默认 `happy-dom`；`views/**`、`components/**`、`smoke/**` 用 environmentMatchGlobs 切 `jsdom`
- 别名 `@ → client/src`；include 路径 `../tests/client/**/*.test.{js,mjs}`
- globals: true（describe/it/expect 免 import）

### 如何跑单个模块测试

```bash
# Python —— 项目根执行
pytest                                    # 全量（tests/）
pytest tests/server/api                   # 某目录
pytest tests/server/api/test_auth.py      # 某文件
pytest tests/server/api/test_auth.py -k login    # 按关键字筛 case
pytest tests/strategy_exec                # strategy_exec 子域
pytest tests/hq                           # 行情服务
pytest tests/server/test_layer_dependencies.py  # 分层架构约束

# 需要活 broker 的集成脚本（默认被 ignore）
pytest tests/server/rpc/test_rpc.py --override-ini="addopts="

# 前端 —— client/ 目录
npm run test -- components/trade/TodayOrdersPanel.test.js
npm run test -- --grep 某用例名

# e2e（先起服务: uv run python scripts/evctl.py start）
uv run python scripts/e2e/test_orders_e2e.py
```

## 修改指南

- 新增 server 测试放 `tests/server/<层>/test_*.py`；文件内可沿用裸名 import（conftest 别名已兜底），但新代码建议直接 `from server.x import y` 限定名
- 新增前端测试放 `tests/client/<对应子目录>/Xxx.test.js`，无需改 vitest 配置（include 通配已覆盖）
- 连接真实外部服务（RabbitMQ/MySQL/行情）的测试不要进 `testpaths` 默认收集：要么放 `scripts/e2e/`，要么加入 `--ignore`
- 测试内不得依赖交易时段（收市 503 是正常行为）：用 `pytest.skip` / e2e 的 `_skip` 字段按时段跳过
- 改 `server/tables` 或 ORM 后跑 `pytest tests/server/models` 验证 Base 注册无冲突
