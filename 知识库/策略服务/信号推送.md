# 信号推送

## 对应代码路径

- `e:/EvTrade/strategy_exec/strategy_exec/signal/publisher.py`（RabbitMQ publisher）
- `e:/EvTrade/strategy_exec/strategy_exec/signal/types.py`（Signal 数据类）
- `e:/EvTrade/strategy_exec/strategy_exec/engines/backtrader/adapter.py`（调用方：ProjectStrategy._publish）

## 功能概述

signal/ 模块定义策略交易信号的统一表示（`Signal`）与 RabbitMQ 推送通道（`SignalPublisher`）：策略引擎（回测/实盘）在 `buy_signal()/sell_signal()` 中构造 Signal，经 `strategy.exchange`（topic, durable）以 `routing_key=stock_code` 发布；EvTrade 主服务的 signal_consumer 消费 `EvTrade.StrategySignal` 队列后调 `POST /api/orders/place` 下单。publisher confirms + 指数退避重试保证可靠送达。

## 文件清单

| 代码文件 | 作用 |
|----------|------|
| `types.py` | `SignalType` 枚举、`Signal` dataclass、`signal_to_payload()` / `payload_to_signal()` 序列化 |
| `publisher.py` | `SignalPublisher`（单连接 + publisher confirms）、`SignalPublishError`、`get_publisher()` / `close_publisher()` |

## 核心实现

### types.py — SignalType 与 Signal

```python
class SignalType(str, Enum):
    BUY = "BUY"
    SELL = "SELL"
    INFO = "INFO"   # 用户脚本仅记录, 不下单
```

`Signal` dataclass 字段（即 RabbitMQ 消息体全部字段）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `task_id` | int | 触发信号的任务 ID |
| `user_id` | int | 用户 ID |
| `script_id` | str | 策略脚本 ID |
| `signal_type` | SignalType | BUY / SELL / INFO |
| `stock_code` | str | 标的代码（如 `600519.SH`，取自 `self.data._name`） |
| `price` | float | 信号价格 |
| `volume` | int | 下单数量 |
| `price_type` | str | `"limit"`（默认）/ `"market"` —— 下单价格类型 |
| `indicators` | dict | 触发时的指标快照（如 `{ma5, ma20, rsi}`），写 audit + payload |
| `msg` | str | 人类可读说明（如「金叉: ma5=… 上穿 ma20=…」） |
| `ts` | str | 信号创建时间（UTC isoformat，默认 now） |
| `stime` | str | 触发信号的 K 线时间 `YYYYMMDDHHMMSS`（`ProjectStrategy._bar_time()`），空=未知 |
| `mode` | str | `"backtest"` / `"live"` —— 区分回测模拟信号与实盘信号（消费端按此判断是否真下单） |
| `trace_id` | str | uuid4，全链路追踪 ID（= RabbitMQ message_id，审计关联） |
| `parent_task_id` | int? | 母单归因：signal_consumer 读此字段写 `orders.task_id`；None = 非母单 |
| `strategy_name` | str | 子单 user_def 用 |

序列化：`to_payload()`（enum→str）→ `signal_to_payload(signal) -> str`（JSON，`ensure_ascii=False`）；反序列化 `payload_to_signal(payload: dict) -> Signal`（EvTrade 消费侧用，容错默认值）。

### publisher.py — RabbitMQ 拓扑与可靠性

拓扑（与 EvTrade signal_consumer 约定）：

```
strategy_exec ──publish──► strategy.exchange (TOPIC, durable=True)
                               routing_key = stock_code  (如 "600519.SH")
                                    │ binding
                                    ▼
                          EvTrade.StrategySignal 队列 (EvTrade 侧声明消费)
```

配置项（config.py）：`EVTRADE_STRATEGY_EXCHANGE_NAME`（默认 `strategy.exchange`）、`EVTRADE_STRATEGY_SIGNAL_QUEUE`（默认 `EvTrade.StrategySignal`，本服务不声明仅文档约定）、`EVTRADE_STRATEGY_PUBLISH_CONFIRM_TIMEOUT`（默认 5s）、`EVTRADE_STRATEGY_PUBLISH_RETRIES`（默认 3）。

`SignalPublisher.connect()`：

- `aio_pika.connect_robust(url)` 建健壮连接 → `channel(publisher_confirms=True)`（broker 确认后才返回）→ `declare_exchange(topic, durable=True)`。
- **记录主 event loop**（`self._loop = asyncio.get_running_loop()`）：回测在 `asyncio.to_thread` 中跑，策略 `next()` 是同步代码，publish 需 `asyncio.run_coroutine_threadsafe` 投回主 loop；否则 `asyncio.run()` 新建 loop 访问主 loop 的 aio_pika 连接会报 "Task attached to a different loop"。
- `asyncio.Lock` 防并发重连；已连接则幂等返回。
- api/internal.py 在派发后台任务前会先 `await get_publisher().connect()` 预连接（减少首次 publish 延迟 + 绑定主 loop；缺失时整批任务会因临时 loop 关闭报 "Event loop is closed" 而 failed）。

`publish_signal(signal) -> str`：

- Message 属性：`content_type="application/json"`、`delivery_mode=PERSISTENT`、`message_id=signal.trace_id`、headers `{task_id, user_id, script_id, signal_type}`。
- 重试循环：`TimeoutError` / `AMQPException` → 指数退避 `2**(attempt-1)` 秒（1s, 2s, 4s）；重试耗尽抛 `SignalPublishError`（caller 即 `ProjectStrategy._publish` 捕获后调 `notify_signal_published("", ok=False)` 并返 None）。
- 成功返 `trace_id`。

单例：`get_publisher()` lazy init；`close_publisher()` 应用关闭时调用。

### 跨线程调用链（回测场景）

```
cerebro.run()  [asyncio.to_thread 线程]
  └─ strategy.next()  (sync)
       └─ buy_signal() → ProjectStrategy._publish()
            └─ asyncio.run_coroutine_threadsafe(publish_signal(signal), publisher.loop)
                 .result(timeout=10)          # 同步等结果
```

live 场景则在主 loop 内直接 await 路径（LiveRunner 手动调 next()，同样走 _publish 的线程安全封装）。

## 依赖关系

- 上游：`engines/backtrader/adapter.py`（构造 Signal 并 publish）、`api/internal.py`（预连接）。
- 下游：RabbitMQ broker → EvTrade signal_consumer（消费 `EvTrade.StrategySignal`，反序列化用 `payload_to_signal`，读 `parent_task_id`/`mode`/`price_type` 等字段下单）。

## 修改指南

- 加消息字段：改 `Signal` dataclass + `to_payload`/`payload_to_signal` 两端，**必须**同步 EvTrade signal_consumer 的解析与下单映射（orders 表字段）。
- 改 exchange/queue 名：`.env` 三个 `EVTRADE_STRATEGY_*` 变量即可，无需改码；但 EvTrade 侧声明需一致。
- price_type 目前仅 `limit`/`market` 语义，新增类型需 QMT 侧下单接口支持。
- 重试次数/超时调节：`EVTRADE_STRATEGY_PUBLISH_RETRIES` / `EVTRADE_STRATEGY_PUBLISH_CONFIRM_TIMEOUT`；注意 `_publish` 的 `future.result(timeout=10)` 是独立硬超时，重试总时长可能阻塞 next()，调大 retries 时评估对回测速度的影响。
