# 历史行情 (broker his_hq)

## 链路

```
strategy_exec.run_backtest()
  └─ strategy_exec.market_data.hq_history.fetch_his_bars(
       stock_code, start_date, end_date, user_period, fields
     )
       ├─ [chunked 调度] his_hq_chunk_enabled=True (默认):
       │    [start, end] → N 段 (每段 ≤ his_hq_chunk_days=10 天)
       │    └─ 串行 N 次 _fetch_one_chunk (每段独立 30s 超时, 任一段失败整体 raise)
       ├─ [broker 调用] 固定 period='1m' fields=['close'] 调 broker
       │    └─ aio_pika publish 到 quota_his.exchange/EvTrade.ReqHisHq
       │         └─ broker his_hq 异步答到 ans_queue (1m K 线, 仅 close)
       ├─ [拼凑] N 段 1m bars 合并 + sort by stime (broker 内部顺序可能乱)
       └─ [strategy_exec 端聚合] aggregator.aggregate_bars(bars_1m, user_period)
            ├─ 1m  → 透传
            ├─ 5m/15m/30m/60m → 按 N 分钟桶聚合 OHLCV
            └─ 1d  → 按 A股交易日历聚合 (跳过 Sat/Sun)
```

## 关键架构 (change `2026-08-30-his-hq-aggregate-bars`)

**Why**: broker his_hq **只返 1m close**（用户 2026-08-30 实测确认），其他周期 (1d/5m/15m/30m/60m) 在 strategy_exec 端按 1m + 时间戳自己聚合。

**永远不 mock**（用户拍板 2026-08-30）：删 `his_hq_test_mode` 参数，broker 在线就用 broker 数据，broker 不在线直接 502。

**Broker 接口能力**（实测 `iquant/quota_his.py:73-153`）：
- 接收 `period` 参数（`tick / 1m / 5m / 15m / 30m / 1h / 1d`）
- 调 `context.get_market_data_ex(...)` 拿数据（xtquant / QMT Windows 真实接口）
- broker stub 环境只返 close 字段，其他 0

**strategy_exec 端聚合**（`strategy_exec/market_data/aggregator.py`）：

| user_period | 聚合逻辑 | 输出 K 线数 |
|-------------|---------|-----------|
| `1m` | 透传 (无聚合) | 同 1m bars 数 |
| `5m` | 每 5 根 1m 聚合 1 根 (N=5):<br>open=第一根 close<br>high=max(close)<br>low=min(close)<br>volume=sum | 1m_bars / 5 |
| `15m` | N=15 | 1m_bars / 15 |
| `30m` | N=30 | 1m_bars / 30 |
| `60m` / `1h` | N=60 | 1m_bars / 60 |
| `1d` | 按 A股交易日历聚合 (跳过 Sat/Sun, 09:31~11:30 + 13:01~15:00) | 实际交易日数 |

**OHLCV 计算规则**:
- `open` = 桶内第一根 1m 的 close (broker 1m 不带 OHL, 用 close 兜底)
- `close` = 桶内最后一根 1m 的 close
- `high` = max(close) (broker 1m 不带 high, 用 close 兜底)
- `low` = min(close) (broker 1m 不带 low, 用 close 兜底)
- `volume` = sum(volume) — broker 1m 不带 → 0
- 实际生产 broker (xtquant) 会返完整 OHLCV, aggregator 优先用 broker 字段

**stime 格式**:
- 1d → `YYYYMMDD150000` (14位, 15:00 收盘, Backtrader `format="%Y%m%d%H%MSS"` 兼容)
- 其余 → `YYYYMMDDHHMMSS` (14位, 桶起点, e.g. 5m `09:30/09:35/...`)

**A股交易日历**:
- 周末 (Sat/Sun) 不生成 K 线 (broker 1m 数据本身不含, aggregator 兜底)
- 交易时段: 09:31~11:30 + 13:01~15:00 (broker 1m 数据自动覆盖, aggregator 兜底)
- 午休 11:31~12:59 broker 1m 数据空 (自动跳过)
- 半日 (e.g. 最后交易日 13:30 提前收盘) 仍按 1d 聚合

## Chunked Fetch (change `2026-08-30-his-hq-chunked-fetch`)

**Why**: 长区间回测 (30 天/1 年) broker 单次 fetch 30s 超时 (`evtrade_his_hq_req_timeout=30`)。实测 30 天 33.7s (broker stub 边界)，真实生产 broker 数据量更大必超时。用户拍板: **拆 10 天/批，全部取到后拼成完整 K 线**。

**配置** (`strategy_exec/config.py`):

| 字段 | 默认 | 范围 | env |
|------|------|------|-----|
| `his_hq_chunk_days` | 10 | 1-30 | `EVTRADE_HIS_HQ_CHUNK_DAYS` |
| `his_hq_chunk_enabled` | True | bool | `EVTRADE_HIS_HQ_CHUNK_ENABLED` |

**行为**:
- 开启 (默认): `_iter_chunks(start, end, chunk_days)` 拆 N 段 → 串行 `_fetch_one_chunk` → 拼凑 + sort by stime → aggregator
- 任一段 raise → 整体 raise `HQHistoryError("chunked fetch failed at chunk i/N (cs~ce): ...")`，**不返部分数据** (原子性)
- 关闭 (`his_hq_chunk_enabled=False`): 保留原行为 1 次全区间 fetch (向后兼容)
- 外部接口 `fetch_bars(stock, start, end, period, fields)` 签名不变；串行 fetch，不并发
- 拆段规则: 每段 ≤ chunk_days 天，末段可不足，跨年自动 rollover，单日区间 1 段

**段数**: 30 天 → 3 段 / 90 天 → 9 段 / 1 年 (365 天) → 37 段

## Cache (minute_bars) — change 2026-08-30-his-hq-cache-minute-bars

**Why**: 长区间回测（30 天/1 年）每次都跑 broker his_hq 慢（broker 端 30s 超时 + 单源真相），broker 不在线时用户看到「数据不出来」。**复用 his-quote-backfill (2026-08-30) 已采集的 1m K 线**（174,240 条 `159992.SZ` 20230830~20260828）。

**新数据流 (cache 开启)**:
```
fetch_bars(stock, start, end, user_period, fields):
  ├─ 1. query_minute_bars(stock, start, end) → cached_bars
  │
  ├─ 2. case A — FULL HIT (covered >= 50% total):
  │    返 cached_bars, 跳过 broker
  │
  ├─ 3. case B/C — 部分/无覆盖:
  │    a. chunked_enabled=False → 1 次拉全区间 + 写回 cache
  │    b. chunked_enabled=True → 拆 N 段 (默认 10 天/批):
  │       - _chunk_fully_cached (按日, 跳周末) → 跳 broker
  │       - 缺天 → broker + 写回 cache
  └─ 4. aggregator 1m 聚合 (1d/5m/15m/30m/60m)
```

**新配置**:
| 字段 | 默认 | env override |
|------|------|--------------|
| `his_hq_cache_enabled` | True | `EVTRADE_HIS_HQ_CACHE_ENABLED=1` |

**新增文件** `strategy_exec/strategy_exec/data_access/minute_bars.py`:
- `query_minute_bars(stock, start, end) -> List[Dict]` - 查 minute_bars (async + asyncio.to_thread)
- `upsert_minute_bars(stock, bars) -> int` - 批量 upsert (executemany + ON DUPLICATE KEY UPDATE, 幂等)
- `is_full_cover(cached, start, end) -> bool` - cached 覆盖 ≥ 50% 区间
- `_chunk_fully_cached(cached, cs, ce) -> bool` - cached 完整覆盖某 chunk (按日, 跳周末)

**修改文件**:
- `strategy_exec/strategy_exec/main.py` - sys.path fix (strategy_exec 直连 EvTrade DB, 加根目录到 sys.path)
- `strategy_exec/strategy_exec/market_data/hq_history.py` - fetch_bars 入口加 cache 调度; 抽 `_chunked_fetch_with_cache` / `_chunked_fetch_only`
- `strategy_exec/strategy_exec/market_data/aggregator.py` - broker 返 '0.0' 占位时跳过 (不当合法值), 用 close 兜底
- `strategy_exec/strategy_exec/engines/backtrader/backtest.py` - `_make_pandas_data_feed` open NaN 用 close 兜底 (修"缺 open 列"报错)

**实测 (2026-08-30)**:

- aggregator → 243 1d K 线 (真实 close=0.799 等)

**测试覆盖** (188 passed):

## Audit Batch Write — change 2026-08-30-audit-batch-write

**Why**: `run_backtest` 对每个生成的 signal 调一次 `write_audit()` 单条 INSERT+commit, 12,040 signals 需 6 分钟+, `status='finished'` 延迟确认。

**修法**:
- `strategy_exec/data_access/strategy_task.py` 加 `write_audit_batch(rows: List[Dict], batch_size=1000) -> int` (executemany + 自动分批)
- `backtest.py` 改为收集 List[Dict] → `write_audit_batch(audit_rows)` (一行调用)

**实测 speedup (60x)**:
| signals | 旧版 (单条) | 新版 (batch) | speedup |
|---------|------------|--------------|---------|
| 63 (5d 1m) | 11s | <1s | 10x |
| 12040 (3.5y 1m) | 6min+ (卡 running) | 12s + finished 自动 | **60x** |

**实测 (2026-08-30)**:
- task30 (3.5y 1m, 12040 signals): **2min50s 跑完** vs 原 task26 卡6 分钟+
- pnl/trades_count 正确写入 (task30 pnl=-17.0, trades=12040)
- audit 12040 行完整 (与原 write_audit 语义一致)
- 短区间 task29 (63 signals): 3 秒跑完 (与原 11 秒一致)

**不破坏语义**:
- pnl/trades_count 数值与原 write_audit 完全一致 (task25 vs task28 同 pnl=16.20/6 signals)
- indicators/payload JSON 序列化逻辑不变
- 单条 write_audit 函数保留 (live.py/sweep 仍可用)
- 异常 fail-safe: DB 错误返 0, 不影响回测主流程

**测试覆盖**:
- `tests/strategy_exec/test_audit_batch_write.py` (10 cases): 单批/多批/空/JSON/异常/batch_size 边界
