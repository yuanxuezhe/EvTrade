# 策略服务架构概览

## 对应代码路径

- `e:/EvTrade/strategy_exec/`（服务根目录）
- 设计文档：`e:/EvTrade/openspec/changes/archive/2026-08-09-strategy-exec-service/design.md`

## 功能概述

strategy_exec 是 EvTrade 项目的**策略运行独立服务**（独立进程，默认端口 8001），负责执行用户编写的 Backtrader 策略脚本（回测 / 实盘 / 参数扫描），并把产生的交易信号通过 RabbitMQ 推回 EvTrade 主服务下单。

核心定位（设计决策）：

- **独立进程**：与 EvTrade 主服务（FastAPI :8000）完全隔离，不依赖 EvTrade 任何 Python 代码；策略崩溃不影响交易主链路。
- **共享 MySQL**：与 EvTrade 同库，共享 `strategy_script` / `strategy_task` / `strategy_script_audit` 三张表（表结构由 `server/schema.yml` + `sync_schema.py` 维护，strategy_exec 仅消费）。
- **RabbitMQ 信号推送**：策略触发买/卖信号 → 发到 `strategy.exchange`（topic）→ EvTrade 的 signal_consumer 消费 `EvTrade.StrategySignal` 队列 → `POST /api/orders/place` 下单。
- **HTTP 任务控制**：EvTrade 后端通过 `/internal/run-task`、`/internal/stop-task` 等 4+1 个端点转发任务指令（`X-Internal-Token` 校验）。
- **行情来源**：历史 K 线走 RabbitMQ `quota_his.exchange`（broker his_hq 通道）；实盘 tick 直连 hqserverd WS（:8765，Rust 版行情服务 hqserverd），不经 EvTrade。

## 核心实现

### 整体数据流

```
前端 ScriptTask.vue ──HTTP──► EvTrade :8000 (forward.py 转发)
                                  │  POST /internal/run-task
                                  ▼
                       strategy_exec :8001 (api/internal.py)
                                  │
              ┌───────────────────┼────────────────────┐
              ▼ backtest          ▼ live                ▼ sweep
        fetch_his_bars       LiveRunner 连 hqserverd    并发 run_backtest
        (RabbitMQ his_hq)    WS :8765 收 tick 聚 1m
              │                   │                     │
              └───────► run_backtest / strategy.next() ─┘
                                  │ buy_signal()/sell_signal()
                                  ▼
                    SignalPublisher → strategy.exchange (topic)
                                  │ routing_key=stock_code
                                  ▼
              EvTrade signal_consumer 消费 EvTrade.StrategySignal
                                  │ POST /api/orders/place
                                  ▼
                            QMT broker 真实下单
```

回测/实盘过程中的状态与结果**直接写共享 MySQL**：`strategy_task.status/progress/backtest_result/live_signals`、`strategy_script_audit`（每条信号一行审计）。

### 与 EvTrade 主服务的边界

- `strategy_script` 表：strategy_exec **只读**（EvTrade 是唯一写方，spec REQ-SE-005）。
- `strategy_task` 表：双方都写 → 全部 UPDATE 走乐观锁（`version` 字段，冲突重试 3 次）。
- 任务行由 EvTrade **预建**（批次模型）：单次回测 1 行、扫描批次 N 行（共享 `strategy_id` + `batch_no`），strategy_exec 只负责执行，不自建 task。
- 回测最优参数回写 `strategy.best_params`（单次回测立即写；扫描批次由 sweep 统一写 top1）。

## 依赖关系

- 上游：
  - EvTrade 主服务 :8000 —— HTTP 任务指令转发（唯一调用方）
  - RabbitMQ —— broker his_hq 历史行情应答
  - hqserverd :8765 —— 实盘 tick（WS，Rust 版行情服务，见《行情服务/hqserver说明》）
  - MySQL（evtrade 库，192.168.10.2:33066）
- 下游：
  - RabbitMQ `strategy.exchange` —— signal 消息（EvTrade signal_consumer 消费）
  - RabbitMQ `strategy.exchange` routing_key `task.progress.*` —— task_progress 消息（EvTrade task_progress_consumer 消费 → ws_manager.broadcast task_progress_update）
  - 共享 MySQL 三表 + `strategy.best_params` + sys_config (rpc_test_mode / his_hq_test_mode 开关)

## 修改指南

- 新增端点：在 `api/internal.py` 加路由并挂 `verify_internal_token` 依赖，同步更新 EvTrade 侧转发 endpoint。
- 新增引擎（如 vnpy）：参照 `engines/backtrader/` 的 adapter（统一继承入口）+ backtest/live 分离结构。
- 修改信号格式：改 `signal/types.py` 后**必须**同步 EvTrade `signal_consumer` 的反序列化（`payload_to_signal`）。
- 修改 DB 写入：所有 `strategy_task` UPDATE 保持乐观锁模式，勿绕过 `data_access/strategy_task.py`。
- 配置变更：只允许 `STRATEGY_EXEC_*` / `EVTRADE_*` / `HQ_*` / `SANDBOX_*` 四个前缀（config.py 设计原则），同步更新 `.env.example` 与本知识库《入口与配置》。
