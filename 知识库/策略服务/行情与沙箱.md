## 功能概述

market_data/ 提供两类行情接入：`hq_history` 通过 RabbitMQ `quota_his.exchange` 请求 broker（xtquant/QMT his_hq 服务）拉历史 K 线（回测/扫描用）；实盘 tick 由 `engines/backtrader/live.py` 直连 hqserver WS（:8765），`hq_ws_client.py` 是为未来统一封装留的占位。sandbox/loader.py 负责把用户 Python 脚本安全加载为策略类（AST 静态检查 + 受限 namespace + params_schema 注入）。templates/ 提供默认双均线模板供前端编辑器初始化。

## 核心实现

### hq_history.py — broker his_hq 协议

broker his_hq 是 xtquant 侧的 RabbitMQ 通道（协议参考 `iquant/quota_his_test.py`）：

- exchange：`quota_his.exchange`（TOPIC, durable=True）
- 请求队列：`EvTrade.ReqHisHq`（broker 监听）
- 请求体：**msgpacket 二进制格式**（`from msgpacket import MSG_TYPE_REQUEST, MsgPacket`，根 pyproject 经 vendor wheel 安装）
- 应答队列名放在 **body 字段** `ans_queue`，不是 reply_to header

`fetch_bars(stock_code, start_date, end_date, period="1d", fields=None) -> List[dict]` 流程：

1. 默认 `fields = ["open","close","high","low","volume"]`。
2. 构造 MsgPacket：`set_func("his_hq")`，`set_headers(6, "stock_code,start_date,end_date,ans_queue,fields,period")`，`add_row()` 后逐字段 `set_value`（`ans_queue = f"HisHqAns.{uuid4().hex[:8]}"`），`finalize()` + `encode()`。
3. 声明应答队列并绑定：**必须 `durable=True, exclusive=False, auto_delete=False`** —— broker 端会 `queue_declare(target, durable=True)` 后再 publish，若应答队列 exclusive/非 durable，服务端 redeclare 报 406 → 该天被跳过 → 客户端收 0 行超时。
4. 请求 publish 到 `EvTrade.ReqHisHq`；`_weekdays_in(start, end)` 估算期望交易日数（仅日志与提前停止用）。
5. 消费应答：`ans_q.iterator(timeout=EVTRADE_HIS_HQ_REQ_TIMEOUT)`。应答体是文本行协议：首行逗号分隔列名，body 用 `|` 分隔多行、行内 `#` 分隔字段（`_iter_rows` 解析）。服务端按天逐条推送，收满 expected_days 提前 break。
6. **空闲超时 ≠ 失败**：服务端无结束标记，靠 idle 超时判流结束；已收到数据即成功返回，一条未收才抛 `HQHistoryError`（= api 层 502 BROKER_ERROR 提示「确认 QMT 端 his_hq 服务已启动并消费 EvTrade.ReqHisHq」）。
7. finally 删除应答队列（durable 队列不删会残留）。

单例：`get_hq_history_client()`；便捷函数 `fetch_his_bars(...)`。

### hq_ws_client.py — hqserver WS（占位）

Phase 2 简化：live.py 直接用 `websockets.connect(settings.hq_ws_url)` 订阅（`{"type":"subscribe","stock_codes":[...]}` → 收 `{"type":"quote",...}`），断线指数退避重连。本文件 `connect_hq_ws(on_message, subscribe_codes)` 为未来统一封装（多标的/退订/限速）留位，当前无人调用。

demo fallback：代码中无独立 demo 数据源；开发联调时依赖 broker his_hq 真实可用（不可用时 api 层返 502 并给出启动提示文案）。

### sandbox/loader.py — 用户脚本安全加载

`load_strategy_class(code, project_strategy_cls, expected_class_name=None, params_schema=None) -> Type` 五步：

1. **AST 静态检查** `_static_check(code)`：语法错 → ValueError；禁止调用 `_BLOCKED_NAMES`（os.system/os.popen/os.execv*/subprocess.*/socket.*/urllib.request.*/http.client.*/eval/exec/compile/__import__）；`ast.Import` 顶层名命中 `SANDBOX_BLOCKED_MODULES` → SandboxViolationError。
2. **受限 namespace** `SandboxNamespace(project_strategy_cls)`：
   - `__builtins__` 白名单：`__import__`（替换为 `_safe_import`）、`__build_class__`（class 语句必需）、常用异常/内置函数（len/range/sorted/max/min/print/...），无 open/exec/eval/input。
   - 预注入模块：`backtrader(bt)` / `numpy(np)` / `pandas(pd)` / `math` / `json` / `datetime`、`timedelta`、`timezone` / `typing` / `ProjectStrategy`。
   - `__name__="__sandbox__"`；注册 `sys.modules["__sandbox__"]` 为真实 module —— Backtrader 元类 `donew()` 会 `sys.modules[cls.__module__]`，缺失则 KeyError。
3. `exec(code, ns.globals_dict)`：SandboxViolationError 原样抛，其他异常包 ValueError。
4. **找策略类**：默认取 namespace 里第一个 `ProjectStrategy` 子类（排除基类本身）；指定 `expected_class_name` 则按名校验。
5. **v121+ schema 注入** `_inject_params_from_schema(cls, code, params_schema)`：schema 是 params 唯一真源 —— AST 提取代码内 class 体 `params = (("k", default), ...)` 声明的 key 集合（`_extract_declared_keys_from_source`），与 schema keys 不一致 → ValueError（strict fail-fast，代码无 params tuple 视为合法目标态）；一致则用 `AutoInfoClass._derive(cls.__name__, OrderedDict((p["key"], p["default"]) ...), [])` 覆盖 `cls.params`（必须保持可调用的 Params 类，裸 tuple 会报 "'tuple' object is not callable"）。schema 为空列表则拒绝注入。

`_safe_import(name)`：受信放行 `strategy_exec.engines.backtrader.adapter`（用户脚本 try/except 导入 ProjectStrategy 的兼容写法）；黑名单命中 → SandboxViolationError；白名单（allowed + backtrader/bt/numpy/np/pandas/pd）之外 → SandboxViolationError。

### templates/default_bt_strategy.py — 默认双均线模板

模块级常量（前端 ScriptDev.vue 初始化用，非可执行策略）：

- `DEFAULT_BT_STRATEGY_CODE`：字符串形式的 `MAStrategy(ProjectStrategy)` —— SMA(fast)/SMA(slow)/RSI + CrossOver；金叉且无持仓 → `self.buy_signal(price, volume=self.p.qty, indicators={ma5, ma20, rsi}, msg=...)`；死叉且有持仓 → `self.sell_signal(..., volume=self.position.size)` 全仓平；override `notify_signal_published`。顶部 try/except 导入 ProjectStrategy，离线编辑退化为 `bt.Strategy`。
- `DEFAULT_BT_STRATEGY_PARAMS_SCHEMA`：`[{key: fast/slow/qty/rsi_period, type: int, min, max, step, default, desc}]`，与模板 params 一致。

模板 params：`fast=5, slow=20, qty=100, rsi_period=14`。

## 修改指南

- his_hq 协议变更（如 JSON 化）：改 `fetch_bars` 的请求构造与 `_iter_rows` 解析，对照 `iquant/quota_his_test.py` 保持一致；应答队列 durable 语义勿动。
- 沙箱白名单加减模块：改 `.env` 的 `SANDBOX_ALLOWED/BLOCKED_MODULES` 即可（运行时经 `_safe_import` 生效）；函数级黑名单改 `_BLOCKED_NAMES`。
- 新增模板策略：放 `templates/`，保持「CODE 字符串 + PARAMS_SCHEMA 常量」成对导出，并让 schema 与代码 params 严格一致（strict 校验会拒绝不一致的脚本）。
- live 多标的订阅落地时：把 live.py 的直连逻辑迁入 `hq_ws_client.py`，保持 LiveRunner 单标的接口不变。
