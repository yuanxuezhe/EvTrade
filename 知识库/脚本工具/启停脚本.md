# 启停脚本

## 对应代码路径

- `scripts/evctl.py`（唯一入口，跨平台单一 Python 文件，仅用标准库）
- `scripts/README.md`（配套说明）
- `openspec/specs/dev-process-control/spec.md`（能力级 spec）

## 功能概述

EvTrade 开发期进程生命周期管理器。统一管理 5 个默认服务 + 1 个可选服务的 `start` / `stop` / `restart` / `status` / `logs`，在 Linux / Windows / git-bash 三平台行为一致。通过 `.pids/` 记录真实 PID、`.logs/` 收集 stdout+stderr，消除散落 shell 脚本的端口 fallback 与孤儿进程问题。

## 文件清单

| 代码文件 | 作用 |
|----------|------|
| `scripts/evctl.py` | 启停控制器主脚本（服务表、平台进程工具、spawn/stop/status 逻辑） |
| `scripts/.logs/<name>.log` | 各服务日志（每次 start/restart 前清空 truncate） |
| `scripts/.pids/<name>.pid` | 各服务真实 PID（`Popen` 返回值，非壳进程） |
| `scripts/README.md` | 用法文档（动作×服务矩阵、端口、常见问题） |

## 核心实现

### 服务表与端口（`SERVICES` 字典，evctl.py:169-211）

| 服务 | 端口 | 启动命令 | 工作目录 | preflight 预检 |
|------|------|----------|----------|----------------|
| `backend` | 8000 | `python -m uvicorn server.main:app --host 0.0.0.0`（`--ws-ping-interval 20 --ws-ping-timeout 60`） | 项目根 | `uvicorn` |
| `frontend` | 50998 | `node client/node_modules/vite/bin/vite.js --host 0.0.0.0 --strictPort` | `client/` | 无 |
| `hqserver` | 8765 (WS) | `hq/hqserverd/target/release/hqserverd[.exe]`（Rust 二进制；fallback `cargo run --release --manifest-path hq/hqserverd/Cargo.toml`） | `hq/` | 无 |
| `strategy_exec` | 8001 | `python -m uvicorn strategy_exec.main:app`（从 `strategy_exec/.env` 加载环境变量） | `strategy_exec/` | `fastapi`, `uvicorn` |
| `hermes` | 9119 | `hermes serve`（外部 Hermes Agent daemon，JSON-RPC/WS gateway，AI 助手后端依赖；不走 venv） | 项目根 | callable `_hermes_preflight()`：`hermes` CLI 在 PATH |
| `broker`（可选） | 无 TCP 端口 | `python -u xtquant_api.py`（纯 RabbitMQ publisher） | `iquant/` | `msgpacket`, `aio_pika` |

- `DEFAULT_SERVICES = [backend, frontend, hqserver, strategy_exec, hermes]`——不带参数时的默认目标（2026-08-23 起 hermes 纳入默认，覆盖 ai-agent-panel「不纳入 evctl」决策）
- `hermes` 为外部 Hermes Agent daemon（默认 `127.0.0.1:9119`），CLI 缺失时 `start` 给出安装指引并 fail（不 crash 其它命令）；9119 被占（手动起过）→ skip-success
- `broker` 在 `OPTIONAL_SERVICES`，依赖 QMT 客户端环境（xtquant 本地模块），需显式 `start broker` 启动
- 端口硬编码在脚本顶部，**不读环境变量**；改端口需同步改 `client/vite.config.js` 的 `proxy.target`

### .venv 解释器继承

用 `uv run python ./scripts/evctl.py ...` 启动时，`sys.executable` 自动指向根 `.venv` 的 Python，所有 Python 子进程（uvicorn / strategy_exec）继承同一解释器，**无需手动激活 venv**。strategy_exec 也复用根 `.venv`（依赖装在根 `pyproject.toml`）。
**hqserver 为 Rust 二进制** `hq/hqserverd/`，不走 Python 解释器（依赖去掉 `aio_pika` / `websockets`）。evctl 通过 `_hqserverd_cmd()` 选择：环境变量 `HQSERVERD_BIN` > `target/release/hqserverd` > `cargo run --release`。

### 命令用法

```bash
uv run python ./scripts/evctl.py start                       # 起全部 5 服务
uv run python ./scripts/evctl.py stop                        # 停全部（反序）
uv run python ./scripts/evctl.py restart                     # 停 + 清日志 + 起
uv run python ./scripts/evctl.py status                      # 端口/pidfile/健康检查
uv run python ./scripts/evctl.py logs                        # 打印所有服务日志尾 50 行
uv run python ./scripts/evctl.py start backend               # 只起后端
uv run python ./scripts/evctl.py stop frontend hqserver      # 停指定多个
uv run python ./scripts/evctl.py logs strategy_exec          # 只看某服务日志
uv run python ./scripts/evctl.py start hermes                # 只起 hermes serve（默认已随 start 起）
uv run python ./scripts/evctl.py start broker                # 显式启动可选服务
```

退出码：`0` 全部成功；`1` 部分失败；`2` 参数错误（未知动作/服务名）。

### start 流程（`start_service`，evctl.py:557）

1. `_clear_log` 清空旧日志（truncate 不删除）
2. 端口占用检查（`find_pid_by_port`）：
   - `frontend` 特例：读占用进程 cmdline，含 `vite`/`esbuild` 视为孤儿（ctrl-C 残留）→ 强杀接管；否则 warn 跳过
   - 其他服务端口被占 → warn 跳过（视为 skip-success）
3. `_preflight_check`：module import 预检 + **callable 预检**（如 hermes CLI 存在性检查，callable 自报失败原因）；失败给出明确缺依赖/缺 CLI 错误
4. `_cleanup_stale_pidfile`：清理死进程的残留 pid 文件
5. `spawn_detached` 后台启动：Windows 用 `DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP`，Linux 用 `start_new_session=True`；stdout+stderr 追加到 `.logs/<name>.log`，PID 写入 `.pids/<name>.pid`
6. 存活检查（0.5s / 1.5s / 3.0s 三轮）：秒挂场景打印日志尾 15 行辅助诊断
7. 若含 backend：先跑 `_pre_schema_check()`（见下），启动完成后 `wait_health()` 轮询 `GET /api/health`（10 次 × 1s）

### backend 启动前 schema 体检（`_pre_schema_check`，evctl.py:673）

- 执行 `sync_schema.py diff` 只报告 drift，**不自动 apply**（历史教训：apply 曾触发 gen_tables 主键丢失导致 login 500、类型 fallback 截断数据）
- 有 drift → WARN 提醒不阻断；`EVTRADE_STRICT_SCHEMA=1` 改为有 drift 拒绝启动（CI 用）；`EVTRADE_SKIP_SCHEMA_CHECK=1` 紧急逃生

### stop 流程（`stop_all`）

- 按 `DEFAULT_SERVICES` **反序**停（hqserver → … → backend，减少前端 WS 断连噪音）
- 优先按 pidfile：`kill_tree` SIGTERM → 等 3s → SIGKILL（Linux 走进程组）；Windows `taskkill /F /T`
- 停完再扫三个端口，残留进程兜底强杀

### restart 额外动作

`_cleanup_logs_before_restart()`：额外清空 `server/logs/*.log|*.jsonl` 与 `/tmp/backend*.log`、`/tmp/mock_ticker.log`、`/tmp/hqserver*.log`、`/tmp/ws_subscribes.log`（历史 nohup 遗留位置）。

### status 输出

每服务三行信息：端口占用（LISTEN pid 进程名 / free）、pidfile 状态（alive / dead / missing）、最后 `GET /api/health` 探测（200 OK / FAIL）。

### 平台差异（库内吸收）

| 操作 | Linux | Windows |
|------|-------|---------|
| 查端口 PID | `ss -ltnp` | `netstat -ano` |
| 读进程 cmdline | `/proc/<pid>/cmdline` | PowerShell `Get-CimInstance`（Win11 24H2 无 wmic） |
| 进程存活 | `os.kill(pid, 0)` | `tasklist /FI /FO CSV` |
| 杀进程树 | SIGTERM→SIGKILL 进程组 | `taskkill /F /T /PID` |

## 依赖关系

- 上游：根 `.venv`（uv 管理解释器）；`client/node_modules/vite`（前端）；`server/.env`、`strategy_exec/.env`（配置）；MySQL/RabbitMQ（backend 启动体检与运行依赖）
- 下游：backend（`server.main:app`）、hqserver（Rust 二进制 `hq/hqserverd/target/release/hqserverd`）、strategy_exec（`strategy_exec.main:app`）、broker（`iquant/xtquant_api.py`）；`sync_schema.py diff` 被 start 流程调用

## 修改指南

- **加新服务**：在 `SERVICES` 字典加一个 `Service(name, port, cwd, cmd, preflight=...)`；默认启动则加入 `DEFAULT_SERVICES`，可选则加入 `OPTIONAL_SERVICES`
- **加外部 CLI 类服务**：参考 `_hermes_cmd()` + `_hermes_preflight()`——cmd 用 `shutil.which(x) or x`（缺失时 import 不 crash），preflight 传 callable 检查 CLI 存在（`_preflight_check` 已支持 callable 分支）
- **改端口**：改顶部常量后同步改 `client/vite.config.js` proxy 与相关 spec
- **改 frontend 命令**：注意 `_vite_cmd()` 绕开 npx 的 Windows `.cmd` 解析坑，直接调 `vite.js`
- **加环境变量类服务**：参考 `_strategy_exec_cmd()` 返回 `{cmd, env}` dict 的写法
- 日志/pid 目录固定为 `scripts/.logs/`、`scripts/.pids/`，删 pid 文件无副作用（下次 start 正常 spawn）
