# 数据与环境工具

## 对应代码路径

- `scripts/init_strategy_exec_env.py`（strategy_exec 环境初始化）
- `scripts/seed_missing_data.py`（基础数据种子）
- `scripts/sync_stocks_from_idb.py`（前端 IndexedDB → stocks 表同步）
- `scripts/mock_ticker.py`（模拟行情 publisher）
- `scripts/cleanup_logs.sh`（日志清理）
- `scripts/verify_change.sh`（OpenSpec change 验收证据包）

## 功能概述

开发环境辅助工具集：初始化 strategy_exec 与 EvTrade 的通信凭证与 MQ 拓扑、给空库补基础数据、从浏览器 IndexedDB 捞回股票列表、在 QMT publisher 无数据时模拟行情 tick、重启前清日志、归档 change 时收集验收证据。

## 文件清单

| 代码文件 | 作用 |
|----------|------|
| `scripts/init_strategy_exec_env.py` | 生成 API token、声明 RabbitMQ exchange/queue |
| `scripts/seed_missing_data.py` | 初始化 order_no_seq / sys_status / 触发全 A 股 stocks 同步 |
| `scripts/sync_stocks_from_idb.py` | 读 IndexedDB 导出 JSON 批量 upsert 到 stocks 表 |
| `scripts/mock_ticker.py` | 按速率向 RabbitMQ `EvQuota` 队列发模拟 tick |
| `scripts/cleanup_logs.sh` | 备份（或直接清空）server/logs 与 /tmp 下历史日志 |
| `scripts/verify_change.sh` | 输出 change 的 git 历史/归档结构/tasks 完成度/健康检查证据包 |

## 核心实现

### init_strategy_exec_env.py（strategy_exec 初始化）

前提：RabbitMQ 已运行（或 `--skip-rabbitmq` 跳过）、`strategy_exec/.env` 已就绪。

```bash
python scripts/init_strategy_exec_env.py                          # 生成 API token + 声明 RabbitMQ
python scripts/init_strategy_exec_env.py --skip-rabbitmq          # 跳过 RabbitMQ 声明
# 可选参数: --rabbitmq-url amqp://...  --evtrade-db-url mysql+pymysql://...
```

执行三步：
1. `secrets.token_hex(32)` 生成 `STRATEGY_EXEC_API_TOKEN`（两服务通信密钥）
2. 自动回写 `strategy_exec/.env` 中的该 token（文件不存在则提示手动添加）
3. 声明 RabbitMQ 拓扑（幂等，`--skip-rabbitmq` 可跳过）：`strategy.exchange`（topic, durable）+ `EvTrade.StrategySignal` 队列（durable，`routing_key=#` 绑定）

关键约束：`STRATEGY_EXEC_API_TOKEN` 在 EvTrade 侧（server/.env）与 strategy_exec 侧**必须一致**。

signal_consumer 调 `/api/orders/place` 的鉴权 `EVTRADE_SERVICE_TOKEN` 现由 server/.env **直配**（2026-08-25 cleanup-ai-remove 删 `/api/auth/grant` 后，本脚本不再请求 grant token，无 `--grant` 参数）。

### seed_missing_data.py（基础数据种子）

`uv run python scripts/seed_missing_data.py`，三段（全部幂等，有数据即跳过）：
1. `order_no_seq`：无行则插入 `(1, 0)`（订单号序列起点）
2. `sys_status`：无行则插入今日 `(trd_date=CURDATE(), status='open')`
3. `stocks` 全 A 股同步：表内已有 >100 行则跳过；否则调 `server.crawler.sources.sina_list.fetch_all_a_codes(use_cache=True)` 拉代码列表并提示通过 `POST /api/sync/stocks` 完成全量（全量约 5500 只、45-50 分钟）

依赖 `EVTRADE_DB_URL`（加载 server/.env.gs 或 .env）。

### sync_stocks_from_idb.py（IndexedDB → stocks）

用法三步：浏览器控制台导出 `EvTrade-stocks` 库 → 存 `data/stocks_from_idb.json` → `uv run python scripts/sync_stocks_from_idb.py [--file /path/to/x.json]`。逐行批量 upsert（保留前端已生成的 short_name）。适合服务器无法联网爬取、用客户端缓存数据恢复 stocks 表的场景。

### mock_ticker.py（模拟行情）

架构位置：QMT publisher 不发数据时，publish 模拟 tick 到 RabbitMQ（旧链路）：

```text
mock_ticker ──RabbitMQ(default exchange, routing_key=EvQuota)──▶ EvQuota 队列
  （旧 Python hqserver 消费后广播 → backend quote_consumer → 前端 WS）
```

**注意**：hqserver 为 Rust `hq/hqserverd`，只通过 UDP 接收 QMT `quota.py` 推送，不再消费 RabbitMQ；backend quote_consumer 改为 WS 直连 `ws://127.0.0.1:8765`（hqserverd）。mock_ticker 仍 publish 到 RabbitMQ EvQuota 队列（脚本未改），因此其模拟数据当前**不会进入新行情链路**；但 31 字段报文格式与 UDP 链路一致。

```bash
python scripts/mock_ticker.py                          # 默认 5 tick/s，14 只默认股票池
python scripts/mock_ticker.py --rate 20                # 20 tick/s
python scripts/mock_ticker.py --codes 600519.SH,300750.SZ
python scripts/mock_ticker.py --price-base 1820        # 统一基准价
python scripts/mock_ticker.py --duration 30            # 跑 30 秒退出（0=永久）
python scripts/mock_ticker.py --batch-size 5           # 每消息合并 5 条 tick（\n 分隔）
python scripts/mock_ticker.py --url amqp://192.168.10.2:5672/
# 另有 --volatility 0.002（波动率）--seed N（可复现）
```

实现要点：
- 消息体为 **GBK 编码的 pipe 分隔 31 字段字符串**（与 `iquant/quota.py:format_quote` 输出格式一致，由 Rust `hq/hqserverd` 经 UDP 接收解析；字段索引对应 `server/services/strategy/quote_consumer.py`）
- 价格随机游走（±5% 夹逼），含开高低收/昨收/累计量额/买卖五档
- publish 到 **default exchange + routing_key=`EvQuota`**（hqserver 实际监听队列；不可发自建 FANOUT exchange，消息进不了队列）

### cleanup_logs.sh

```bash
./scripts/cleanup_logs.sh           # 备份到 /tmp/evtrade_log_backup_<ts>/ 后清空
./scripts/cleanup_logs.sh --hard    # 不备份直接清空
```

清理范围：`server/logs/*.log|*.jsonl`、`/tmp/backend*.log`、`/tmp/mock_ticker.log`、`/tmp/hqserver*.log`、`/tmp/ws_subscribes.log`。用途：重启前清历史日志避免干扰分析（与 `evctl.py restart` 内置清理互补，后者不备份）。

### verify_change.sh（验收证据包）

```bash
bash scripts/verify_change.sh <change-name> [base-ref]   # 例: bash scripts/verify_change.sh 2026-07-08-t0-task-management main
```

输出 7 段证据到 stdout（可被 verify slash command 捕获）：①git log（base..HEAD）②`openspec/changes/archive/<name>/` 归档结构与 spec-deltas ③tasks.md 完成度（`[x]`/`[ ]` 计数与剩余项）④e2e 脚本清单 ⑤backend 健康检查（`http://localhost:8000/health`）⑥逐 commit stat ⑦delta spec 中的 REQ-ID 清单。

## 依赖关系

- 上游：`EVTRADE_DB_URL` / `RABBITMQ_URL` 环境变量；EvTrade backend 运行中（sync 接口）；RabbitMQ 运行中；`server/crawler/`（seed 调 sina_list）
- 下游：`stocks` / `order_no_seq` / `sys_status` 表数据；hqserver 与前端行情链路（mock_ticker）；OpenSpec 归档验收流程（verify_change）

## 修改指南

- **mock_ticker 改字段**：31 字段协议必须与 `iquant/quota.py:format_quote` 和 `server/services/strategy/quote_consumer.py` 索引同步改（`hq/hqserver.py` 已删除，现为 Rust `hq/hqserverd`，字段格式不变）
- **init 环境脚本改拓扑**：exchange/queue 名与 `openspec/specs/strategy-exec/spec.md`、strategy_exec 侧 consumer 配置对账
- **seed 改表**：新增基础数据表时在 `seed_missing_data.py` 加对应幂等 seed 函数并加入 `__main__` 调用
- **verify_change.sh 加证据段**：保持"输出纯 stdout、无交互"约定，段与段用 `=== N. ... ===` 分隔
