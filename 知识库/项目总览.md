# 项目总览

## 一句话定位

A股智能交易终端：Vue3 + FastAPI + msgpacket RPC + XtQuant/QMT 柜台，覆盖行情推送、手动交易、T0 做T、策略回测与实盘的完整链路。

## 四大服务

| 服务 | 端口 | 代码目录 | 职责 |
|------|------|----------|------|
| 前端终端 | :50998 | `client/` | Vue3 + Element Plus + ECharts + Pinia，21 个页面 |
| EvTrade API | :8000 | `server/` | 交易核心、鉴权、系统管理、WebSocket 推送 |
| hqserverd | :8765 | `hq/hqserverd/`（Rust） | QMT quota.py UDP 推送 → 收包后 WebSocket 推前端 |
| strategy_exec | :8001 | `strategy_exec/` | Backtrader 策略回测/实盘，信号经 RabbitMQ 推送 |

## 架构与数据流

```text
┌──────────────┐  REST + WS   ┌───────────────┐  msgpacket RPC  ┌──────────┐
│ Vue3 前端     │─────────────▶│ EvTrade API    │───────────────▶│ RabbitMQ │
│ (:50998)     │◀────────────│ (:8000)       │◀────────────────│          │
└──────┬───────┘   7 频道 WS   └───────┬───────┘  3类push        └────┬─────┘
       │ ws://:8765 直连                  │ signal_consumer 订阅       │ YSWY协议
       ▼                                  ▼                           ▼
┌──────────────┐               ┌───────────────┐               ┌──────────┐
│ hqserverd    │── 行情 WS ──▶│ strategy_exec  │── signal ───▶│ QMT 柜台  │
│ (:8765)      │  /quota.broadcast │ (:8001)  │               │ XtQuant  │
└──────────────┘               └───────────────┘               └──────────┘
```

### 核心数据流

- **下单**：Vue → `place()` → 本地 INSERT(status=48) → `ord_stk` RPC(remark=order_no) → status=49/55 → WS 推 Vue
- **推送**：QMT → `ord_cfm/trd_cfm/pos_push`（xtquant 协议无 pos_cfm/ast_cfm） → push_handlers 写 DB → WS 推 Vue
- **查询**：纯 DB SELECT，不调 RPC；默认 trading_day = 激活日
- **日初**：Admin → `/api/admin/sys-status/init` → 对账 → 查 4 类数据 → 写报告 → 切交易日 → WS broadcast
- **策略信号**：strategy_exec 跑 Backtrader → signal → `strategy.exchange` → EvTrade signal_consumer → `/api/orders/place` 自动下单

## Git 应急预案（对象库损坏恢复）

### 事故特征

`git stash pop` 失败 / refs 目录消失 / loose objects 丢失 / pack 的 .pack 文件缺失。此时**工作区文件不受影响**（stash 只动 git 对象库），所有未提交改动的实体内容仍在磁盘上。

### 禁止事项（先读这里）

- **对象库可疑时禁止 `git gc`**——refs 已丢失的情况下 gc 会连带删除全部无引用历史，只能靠远程 fetch 救回
- **禁止盲目 `git stash` 暂存大量改动**——需要暂存时改用临时分支：`git switch -c backup/wip && git commit -am "wip"`
- 修复过程中引用丢失对象的 commit 会触发 hooks 报错，用 `git commit --no-verify` 绕过

### 恢复步骤

1. **找锚点**：`git verify-pack -v .git/objects/pack/*.idx | grep commit | tail -5` 找 pack 中最新可用提交；配合 `cat .git/logs/HEAD`（reflog 文件）定位断链位置
2. **重建分支**：`echo <锚点commit> > .git/refs/heads/master`
3. **重建 index**：index 引用丢失对象时直接 `rm -f .git/index && git add -A`（若 HEAD 的 tree 对象也丢失，跳过 status 直接进入下一步）
4. **从远程恢复历史**：`git fetch origin`；若网络不稳先用 `git fetch origin --depth=100` 再 `git fetch --unshallow origin` 补全
5. **嫁接工作区**：`git reset --soft origin/master`，把工作区全部内容 staged 到旧历史上
6. **提交并推送**：单个恢复提交写明恢复了哪些丢失提交的内容，立即 `git push origin master` 备份

### 验证

`git fsck` 无错误、`git log --oneline | wc -l` 数量正常、`git status` 工作树干净、Python 全量 `py_compile` 编译通过。
